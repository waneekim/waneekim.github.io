딥시크 DeepInfer 정리, 추론 엔진 오픈소스의 뜻과 쓰는 조건

딥시크 DeepInfer 공개 — 추론 엔진을 오픈소스로 (캐릭터는 AI 이미지 생성)

같은 레시피로 만들어도 식당마다 한 시간에 내놓는 접시 수와 값이 달라요. 주문을 어떻게 나눠 받고, 화구를 어떻게 쓰고, 미리 손질한 재료를 어떻게 다시 쓰느냐가 다르기 때문이에요. AI도 비슷해요. 모델 가중치가 레시피라면, 그 모델로 수많은 사람의 질문에 빠르고 싸게 답하게 하는 ‘추론 엔진’은 주방 운영 시스템에 가까워요.

중국 AI 회사 딥시크(DeepSeek)가 10월 20일 자사 API에서 V4.1 Flash 모델을 돌리는 추론 엔진 DeepInfer를 Apache 2.0 라이선스로 공개했어요. 레시피에 이어 주방 운영법까지 내놓은 셈이에요. 다만 주방 전체는 아니고, 몇몇 부품은 아직 빠져 있어요.

로봇 주방장이 두꺼운 주방 운영 매뉴얼을 다른 식당 로봇 요리사들에게 건네는 장면 — 추론 엔진을 공개한 딥시크를 빗댄 그림 (AI 이미지 생성)

1. 무슨 일: DeepInfer 공개

딥시크는 10월 20일 X(옛 트위터)에서 사내 추론 프레임워크 DeepInfer를 오픈소스로 공개한다고 밝혔어요. ‘V4.1 Flash를 대규모로 돌리는 우리 생산 스택을 공유해, 커뮤니티가 연산 비용과 에너지 사용을 줄이고 AI를 더 싸게 쓰도록 돕겠다’는 설명이에요.

깃허브 저장소와 문서에서 확인한 내용을 표로 옮겼어요.

항목저장소에서 확인한 내용
이름DeepInfer (깃허브 deepseek-ai/DeepInfer)
하는 일딥시크 서비스의 대규모 추론을 맡는 프레임워크
라이선스Apache 2.0 (저장소 LICENSE 파일)
바탕처음에 주로 vLLM을 바탕으로 만듦, SGLang·TensorRT-LLM 참고
지원 모델DeepSeek-V4.1-Flash 하나
지원 장비엔비디아 SM100 GPU, 화웨이 어센드 950 NPU
함께 공개deepseek-recipe(MIT) — API 요청을 모델이 읽는 토큰으로 바꾸는 부품

엔진이 돌리는 모델 V4.1 Flash 1017은 10월 17일에 나왔고, 가중치는 MIT 라이선스로 허깅페이스에 올라 있어요. 딥시크는 앞으로 나올 모델의 추론 코드와 성능 개선도 이 저장소에 계속 올리겠다고 했어요. 10월 21일 기준 저장소에는 별(관심 표시)이 약 1만 6,000개 붙었어요.

2. 추론 엔진이 하는 일

추론(inference)은 학습이 끝난 모델이 질문을 받아 답을 만드는 일이고, 추론 엔진은 그 일을 많은 사람에게 동시에, 빠르고 싸게 해 주는 소프트웨어예요. 같은 모델이라도 엔진에 따라 GPU 한 대가 처리하는 질문 수와 첫 글자가 나오기까지 걸리는 시간이 달라져요.

README에 적힌 주요 기능을 쉬운 말로 옮기면 이래요.

기능쉬운 말로
최적화 커널GPU에서 도는 계산 코드를 딥시크 모델에 맞춰 빠르게 만든 것(FlashMLA·DeepGEMM·DeepEP 등)
병렬 처리모델 안의 ‘전문가’ 부분을 여러 GPU에 나눠 계산
DSpark 추측 디코딩초안 모델이 토큰 몇 개를 먼저 쓰고, 본 모델이 검사해 한꺼번에 받아들임
비동기 스케줄링GPU가 계산하는 동안 CPU가 다음 일을 미리 준비
구조화 출력JSON 등 정해진 형식에 맞춰 답하게 함

딥시크 Q&A 문서는 질문을 읽는 단계(prefill)와 답을 한 토큰씩 쓰는 단계(decode)를 서로 다른 GPU 묶음에 나눠 맡긴다고 설명했어요. 그래서 효율이 나는 최소 단위를 입력 처리 GPU 64개와 답 생성 GPU 64개, 모두 128개로 잡았어요.

딥시크 추론 서비스 한 벌 가운데 이번에 열린 칸(deepseek-recipe·DeepInfer·모델 가중치)과 아직 비공개인 칸(부하 분산·KV 캐시 저장) (직접 제작)

3. 엔비디아와 화웨이 칩을 함께

DeepInfer는 엔비디아 SM100 GPU와 화웨이 어센드 950 NPU 두 가지에서 돌아가요. SM100은 엔비디아 개발자 자료 기준 B200·GB200 같은 블랙웰 데이터센터 GPU(계산 능력 10.0)를 가리켜요. 어센드 950은 화웨이의 AI 가속기(NPU)예요.

딥시크 문서는 처음부터 ‘여러 회사의 가속기를 지원해 장비마다 성능을 끝까지 쓰는 것’을 목표로 삼았다고 적었어요. 다만 묶음 구성이 달라도 같은 결과를 내는 기능과, 같은 입력에 같은 답을 내는 기능은 엔비디아에서만 된다고 README에 적혀 있어요.

로봇 요리사가 가스레인지와 인덕션 위에서 같은 요리를 동시에 만드는 장면 — 엔비디아와 화웨이 칩에서 함께 도는 DeepInfer를 빗댄 그림 (AI 이미지 생성)

어센드 지원은 9월 말부터 이어진 흐름이에요. SCMP에 따르면 딥시크는 9월 30일 어센드용 도구 6가지(TileLang 어센드판, DeepGEMM·DeepEP 어센드판 등)를 공개했고, 어센드 950 128개로 만든 슈퍼노드를 화웨이와 함께 다듬었다고 밝혔어요. SCMP는 이를 미국의 수출 규제 속에서 엔비디아 의존을 줄이려는 중국의 움직임으로 봤어요.

4. 값 경쟁은 얼마나 커질까

딥시크 모델은 이미 싼 편이에요. 10월 21일 딥시크 API 요금표로 V4.1 Flash(1017)의 100만 토큰당 값은 이래요.

구분피크 · 할인 시간대
입력(캐시 적중)0.006달러 · 0.003달러
입력(캐시 미적중)0.3달러 · 0.15달러
출력1.2달러 · 0.6달러

할인 시간대 값은 피크의 절반이에요. 피크는 평일 UTC 1시에서 4시, 6시에서 10시(한국 시각 오전 10시에서 오후 1시, 오후 3시에서 7시)이고, 주말과 중국 공휴일은 모두 할인 시간대예요. 벤치마크 회사 Artificial Analysis(AA)는 이 모델에 지능 지수 45점을 매기고, 평가 과제 하나에 평균 0.26달러가 들었다고 계산했어요(10월 21일 조회). 딥시크 모델의 과제당 비용은 10월 19일 빔 글에서도 비교했어요.

딥시크는 Q&A 문서에서 이 엔진으로 클러스터 하나가 하루 155조 토큰을 처리하고, 할인 시간대 값으로 셈해도 GPU 한 시간당 매출이 38달러라고 적었어요. 회사가 스스로 밝힌 숫자이고, 따로 확인할 방법은 없어요.

‘글로벌 추론 가격 경쟁을 키운다’는 건 매체의 분석이에요. The Decoder의 마티아스 바스티안은 이번 공개가 오픈AI·앤트로픽 같은 서구 회사에 가격 압박을 더한다고 봤고, 미·중 AI 경쟁을 생각하면 정치적 동기도 있을 수 있다고 덧붙였어요.

엔진과 deepseek-recipe가 공개되면, 다른 클라우드 회사도 딥시크 모델을 공식 API와 같은 방식으로 처리해 팔기 쉬워져요. deepseek-recipe는 ‘공식 API와 같은 동작을 커뮤니티 배포에도’ 주려고 냈다고 딥시크가 밝혔어요. 반면 엔진 공개와 함께 딥시크가 요금을 바꾼다는 발표는 10월 21일까지 찾지 못했어요. 미국 AI 회사와 중국 모델 회사 사이의 긴장은 10월 6일 적대적 증류 글에도 정리했어요.

5. 검증: 열린 것과 빠진 것

이번 공개는 딥시크 서비스 전체가 아니라 엔진 부분이에요. README는 이번 판이 오프라인 추론용이라며, 완전한 추론 서비스에 필요한 세 가지가 빠졌다고 적었어요. KV 캐시 시스템, 입력 처리와 답 생성의 분리 운영, 여러 GPU 묶음 사이의 부하 분산이에요.

Q&A 문서는 KV 캐시 관리와 부하 분산이 사내 인프라와 단단히 묶여 있어 아직 공개하지 않았다고 설명해요. KV 캐시는 앞서 읽은 글의 계산 결과를 저장해 두는 것으로, 같은 앞부분이 다시 오면 다시 계산하지 않아도 돼요. 딥시크는 이 캐시를 72시간 넘게 보관하는 것을 목표로 삼았다고 했어요.

성능 그래프도 딥시크가 직접 잰 것이에요. 입력 처리는 SM100 GPU 4개, 답 생성은 64개로 쟀고, 다시 재 볼 스크립트를 함께 올렸어요. 외부 기관의 비교 측정은 10월 21일까지 찾지 못했어요. 딥시크는 내부판과의 차이도 적었어요. 공개한 FlashMLA는 손으로 다듬은 최적화 하나가 빠져 답 생성 커널이 5에서 10% 느리지만, 전체 성능 차이는 최대 5%라고 해요.

지원 모델도 V4.1 Flash 하나뿐이에요. 여러 회사 모델을 두루 돌리는 범용 엔진(vLLM 등)을 바로 대신하는 도구는 아니에요.

💡 핵심DeepInfer는 딥시크 모델을 싸게 돌리는 엔진이 열린 것이에요. 서비스 전체를 따라 하려면 캐시·부하 분산을 직접 갖춰야 해요.

6. 누가 쓰나, 도입 전 점검

개인 PC용이 아니라, GPU 100개가 넘는 설비를 가진 클라우드 회사나 대기업에 맞는 도구예요. README 기준 리눅스, 파이썬 3.12, GCC 13 이상, 그리고 CUDA 13(엔비디아) 또는 CANN 9.2(어센드)가 필요해요. 오프라인 추론 예제는 있지만, 효율이 나는 최소 단위는 앞에서 본 GPU 128개예요.

그래서 대부분의 개발자에게 당장 달라지는 건 크지 않아요. 바뀔 수 있는 건 딥시크 모델을 파는 클라우드 업체들의 값과 속도예요.

딥시크 모델 도입을 검토한다면 볼 곳은 세 가지예요.
① 쓰임새 — API로 쓰면 딥시크·클라우드 업체 요금표만 비교하면 돼요
② 직접 돌린다면 — SM100이나 어센드 950 장비와, 빠진 캐시·부하 분산을 채울 인력이 필요해요
③ 라이선스 — 엔진은 Apache 2.0, deepseek-recipe와 모델 가중치는 MIT로 상업 이용을 허용하는 라이선스예요

⚠️ 주의딥시크 API를 쓰면 요청이 딥시크 서버에서 처리돼요. 회사 자료를 보내기 전에 사내 보안 정책을 먼저 확인하세요. 이 글의 라이선스 설명은 법률 판단이 아니에요.
✅ 한눈에 정리① 딥시크가 10월 20일 추론 엔진 DeepInfer를 공개했어요
② Apache 2.0, 처음에 주로 vLLM을 바탕으로 만들었어요
③ 엔비디아 SM100과 화웨이 어센드 950에서 돌아가요
④ 가격 경쟁을 키운다는 건 매체의 분석이에요
⑤ KV 캐시·부하 분산은 빠졌고, GPU 128개급 도구예요

오늘의 큰 흐름: 오픈 가중치와 추론 비용 경쟁이 붙었어요. 딥시크는 모델 가중치에 이어 그 모델을 싸게 돌리는 엔진까지 열어, 경쟁의 무대를 ‘얼마나 싸게 돌리나’로 넓혔어요.

자주 묻는 질문

Q. 집 PC에서 딥시크를 돌릴 수 있게 된 건가요?

아니요. DeepInfer는 엔비디아 SM100(B200·GB200급)이나 화웨이 어센드 950 같은 데이터센터 장비용이고, 딥시크 문서는 효율이 나는 최소 단위를 GPU 128개로 잡았어요.

Q. vLLM과는 무엇이 다른가요?

README는 DeepInfer를 처음에 주로 vLLM을 바탕으로 만들고 SGLang·TensorRT-LLM을 참고했다고 적었어요. vLLM이 여러 회사 모델을 두루 돌리는 범용 엔진이라면, DeepInfer는 지금 딥시크 V4.1 Flash 하나에 맞춘 엔진이에요.

Q. 딥시크 API 값이 내려가나요?

10월 21일까지 요금 변경 발표는 찾지 못했어요. 지금 V4.1 Flash는 100만 토큰당 입력 0.3달러(캐시 미적중), 출력 1.2달러이고, 할인 시간대에는 그 절반이에요.

Q. 회사에서 써도 되나요?

엔진은 Apache 2.0, deepseek-recipe와 모델 가중치는 MIT로 상업 이용을 허용하는 라이선스예요. 실제 도입 전에는 라이선스 원문과 사내 보안 정책을 확인하세요. 이 글은 법률 판단이 아니에요.
