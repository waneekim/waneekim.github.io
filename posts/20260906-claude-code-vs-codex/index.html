Claude Code vs Codex — 둘 다 돈 내고 써본 사람의 실전 비교

이 비교 글이 흔한 스펙 나열과 다른 이유가 있다. 나는 두 도구로 각각 실물을 만들었다. 가족 여행 앱은 Codex와의 대화로 만들었고(그 기록), 지금 읽고 있는 이 블로그의 운영 시스템 전체는 Claude Code가 굴리고 있다. 같은 사람이 같은 시기에 둘을 다 쓰면서 느낀 차이를 정리한다.

🥊 1. 뭐가 같은 도구인가

둘 다 “말로 시키면 코드를 짜고 실행까지 하는” 코딩 에이전트다. OpenAI의 Codex는 ChatGPT 구독에, Anthropic의 Claude Code는 Claude 구독(Pro 이상)에 포함된다. 즉 이 비교는 사실상 ChatGPT vs Claude 구독 비교의 코딩 편이기도 하다.

둘 다 터미널(CLI)과 에디터 확장, 클라우드 실행까지 제공하는 방향으로 수렴해 왔다. 그래서 기능표는 갈수록 비슷해진다 — 차이는 기능표가 아니라 “일하는 감각”에 있다.

🧳 2. 실물 ①: 여행 앱은 Codex로 — “대화의 힘”

5가족 19명 여행 앱을 만들 때 나는 ChatGPT 안에서 Codex와 대화로 작업했다. 일정 상의부터 앱 생성까지 한 흐름으로 이어진 게 결정적이었다. “첫째 날 비 오면 어떡하지?” 같은 기획 대화를 하다가 그대로 “이 일정으로 앱 만들어줘”로 넘어가는 경험은 확실히 매끄러웠다.

인상적이었던 건 방향 전환이다. 글자 빽빽한 첫 버전을 폐기하고 “전부 보물지도 그림으로”라고 한 마디 던졌을 때, 결과물이 통째로 다시 나왔다. 기획이 유동적인 1회성 결과물에는 이 방식이 잘 맞았다.

🏭 3. 실물 ②: 블로그 공장은 Claude Code로 — “실행의 힘”

반면 이 블로그의 운영 시스템은 성격이 다른 일이다. 사이트 빌드·배포, 이미지 생성, 브라우저 자동화, 발행 기록 관리 — 한 번 만들고 끝이 아니라 매주 돌아가야 하는 시스템이다.

여기서는 Claude Code의 방식이 결정적이었다. 내 컴퓨터의 실제 저장소 안에서 파일을 고치고, 스크립트를 직접 실행해 보고, 실패하면 오류를 읽고 다시 고친다. “배포해줘”라고 하면 빌드부터 결과 URL 확인까지 끝내고 보고한다. 프로젝트 규칙을 CLAUDE.md에 적어두면 계속 지켜지는 것도 운영에는 큰 차이다. (사용법 정리)

⚖️ 4. 실사용에서 느낀 차이 3가지

① 시작 문턱. Codex는 ChatGPT 쓰던 감각 그대로 시작된다. Claude Code는 터미널이라는 첫인상 때문에 문턱이 있어 보이지만, 실제 사용은 채팅과 같다 — 다만 “내 컴퓨터 안”이라는 위치가 다르다.

② 검증 습관. Claude Code는 로컬에서 실행·테스트하며 일해서 “된다고 하고 실제로 안 되는” 경우가 적었다. Codex 대화 방식은 결과물을 내가 열어 확인하는 단계가 한 번 더 필요했다.

③ 반복 작업의 축적. 운영형 프로젝트에서는 규칙·스크립트가 쌓이면서 갈수록 일이 빨라져야 한다. 저장소 전체를 맥락으로 갖고 일하는 Claude Code 쪽이 이 축적에 유리했다.

⚠️ 공정하게 덧붙이면, 두 도구 모두 빠르게 업데이트되는 중이라 세부 기능 차이는 몇 달 단위로 뒤집힐 수 있다. 위 비교는 “방식의 차이”로 읽어주시길.

🎯 5. 그래서 결론

  • 비개발자이고, 만들고 싶은 게 하나 있다 → Codex부터. 쓰던 ChatGPT에서 바로 시작된다
  • 자동화·운영처럼 계속 굴릴 일이 있다 → Claude Code. 내 컴퓨터에서 실행·검증까지 맡길 수 있다
  • 둘 다 해당된다 → 나처럼 둘 다 쓰는 게 답일 수 있다. 나는 기획·이미지는 ChatGPT 쪽, 실행·운영은 Claude Code로 역할을 나눴고 이 조합에 만족한다
