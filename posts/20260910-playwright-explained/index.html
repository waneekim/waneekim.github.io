이 글에는 제휴 링크가 없습니다. 화면은 직접 캡처했고 다이어그램은 직접 제작했습니다.

Playwright 뜻 — AI에게 브라우저를 쥐여주는 도구, 이 블로그가 네이버에 글을 올리는 방법

이 글을 읽고 계신 네이버 블로그판은 제가 손으로 올리지 않았습니다. 제목 입력, 본문 타이핑, 사진 업로드, 크기 조정, 캡션, 카테고리 선택, 태그, 발행 버튼까지 — 전부 Playwright(플레이라이트) 라는 도구가 브라우저를 대신 조작했어요. 지금까지 네이버 39건, 인스타그램 16건이 이렇게 나갔습니다. 이 글은 그 도구가 뭔지, 왜 AI 자동화 이야기에 자꾸 등장하는지, 그리고 제가 55번 발행하며 배운 원칙 하나를 정리합니다.

결론 요약

  • Playwright = 사람이 브라우저에서 하는 클릭·타이핑·스크롤을 코드로 시키는 도구. 마이크로소프트가 만든 무료 오픈소스
  • 원래는 웹사이트 테스트용이었는데, 지금은 AI 에이전트의 손으로 더 많이 쓰입니다 (공식 MCP 서버까지 있음)
  • 제 원칙 하나: 로그인은 사람이, 조종은 코드가. 비밀번호를 코드에 넣지 않고, 사람이 로그인해둔 창에 붙습니다
  • 브라우저 자동화는 사람보다 정확하지만 사람보다 순진합니다 — 그래서 규칙이 필요해요

🧩 1. 한 줄로 — 브라우저에 손을 달아주는 것

브라우저는 원래 사람이 조작하는 물건입니다. 주소를 치고, 버튼을 누르고, 글자를 입력하죠. Playwright는 그 동작을 코드로 적어서 브라우저에 시키는 도구예요. “이 주소로 가서, ‘사진’ 버튼을 누르고, 이 파일을 올리고, 제목 칸에 이 글자를 쳐라.” 이걸 사람 대신 초당 수십 번 정확히 합니다.

이름이 왜 ‘극작가(playwright)‘냐면, 대본을 쓰면 브라우저가 그대로 연기한다는 뜻이에요. 마이크로소프트가 2020년에 공개했고, 크롬·엣지·파이어폭스·사파리 계열 브라우저를 전부 다룰 수 있으며, 파이썬·자바스크립트 등 여러 언어에서 씁니다. 2026년 9월 기준 최신은 1.62 버전이고 무료입니다.

📦 2. 테스트 도구에서 AI의 손으로

원래 용도는 웹사이트 테스트였습니다. “회원가입 버튼이 잘 눌리나”를 매번 사람이 확인하지 않고 코드가 대신 눌러보는 거죠. 개발자들의 도구였어요.

그런데 AI 에이전트가 등장하면서 쓰임이 바뀌었습니다. 에이전트 글에서 “에이전트 = 목표를 주면 도구를 써서 일을 끝내는 AI”라고 했는데, 그 도구 중 가장 강력한 게 브라우저입니다. 세상 대부분의 일이 브라우저 안에서 벌어지니까요. 그래서 마이크로소프트는 AI가 브라우저를 다루게 해주는 Playwright MCP를 공식으로 내놨고, 2026년 릴리스는 아예 “에이전트가 브라우저를 모는 것”을 전제로 설계됐습니다. MCP가 AI에게 손발을 달아주는 표준이라면, Playwright는 그 손이 브라우저를 잡게 해주는 부품이에요.

🔍 3. 실물 — 이 블로그의 네이버 발행

네이버는 글쓰기 API를 2020년에 닫았습니다. 그래서 자동화하려면 사람처럼 에디터를 조작하는 수밖에 없어요. 제 발행 파이프라인이 하는 일은 이렇습니다.

단계Playwright가 하는 일사람이었다면
제목·본문글자 하나당 10ms 간격으로 타이핑 (네이버 에디터가 자동 서식을 거는 패턴은 피해서)복붙 후 서식 정리
사진‘사진’ 버튼 → 파일 선택창에 파일 전달 → 업로드 완료 감지 → 크기 250/400px 지정 → 가운데 정렬 → 캡션 입력장당 30초
발행패널 열기 → 카테고리 드롭다운에서 항목 좌표 클릭 → 태그 7개 → 전체공개 확인 → 발행1분
검증발행 전 전 문단을 읽어 원고와 글자 단위로 대조, 발행 후 게시글의 이미지 수·태그를 다시 읽음눈으로 훑기

저장소에 이 일을 하는 스크립트가 10개, 이번 주에 임시로 만들었다 굳힌 게 27개. 글 한 편의 네이버판은 대본 파일 하나(제목·문단·사진·캡션·카테고리·태그)로 굳혀두고, 매일 아침 릴리스 작업이 그 대본을 Playwright에게 넘깁니다.

⚙️ 4. 핵심 원칙 — 로그인은 사람이, 조종은 코드가

여기가 제일 중요합니다. 브라우저 자동화를 처음 접하면 “코드가 아이디·비밀번호로 로그인하게 하면 되겠네”라고 생각하기 쉬운데, 저는 한 번도 그렇게 하지 않았습니다. 두 가지 이유예요.

  • 비밀번호를 코드에 두면 안 됩니다. 파일이 새면 계정이 새요. 제 저장소 어디에도 네이버·인스타 비밀번호는 없습니다
  • 로그인 자동화는 봇으로 감지됩니다. 네이버·인스타 모두 자동 로그인 패턴을 잡아내고, 걸리면 계정 자체가 위험해져요

대신 이렇게 합니다. 엣지 브라우저를 “원격 조종 문(포트)을 열어둔 채” 띄우고, 그 창에서 사람이 한 번 로그인합니다. Playwright는 새 브라우저를 여는 게 아니라 그 창에 붙어서(connect_over_cdp) 이미 로그인된 상태로 일을 해요. 브라우저 입장에선 사람이 쓰던 창에 사람이 계속 뭔가 하는 것과 구분이 안 됩니다. 제 스크립트에서 이 방식이 39번, 새 브라우저를 여는 방식은 1번(화면 캡처용)이에요.

계정이 두 개(AI 블로그·세차 블로그)면 창도 두 개입니다. 각 창에 한 번씩 로그인해두면 전환 없이 둘 다 다룹니다.

💥 5. 배운 것 — 정확하지만 순진합니다

55번 발행하며 세 번 넘어졌고, 세 번 다 같은 교훈이었어요.

  • 숨은 버튼을 먼저 잡습니다. “발행”이라는 글자가 든 버튼을 찾으라고 했더니, 화면엔 안 보이는 ‘예약 발행 0건’ 버튼을 먼저 잡고 30초를 기다리다 실패했어요. 사람은 보이는 버튼만 누르지만 코드는 안 보이는 것도 찾습니다 → “보이는 것 중에서” 라는 조건을 넣어야 합니다
  • 보이지 않는 공백에 걸립니다. 카테고리 이름 ‘세차 장비·용품’을 찾으라고 했는데 못 찾았어요. 화면엔 똑같이 보이는데 글자 사이에 특수 공백이 섞여 있었죠. 사람 눈엔 같지만 코드엔 다른 글자입니다 → 비교 전에 공백을 정리하는 한 줄이 필요했습니다
  • 파일 선택창이 가끔 안 열립니다. GIF를 올린 직후 다음 사진의 파일 선택창이 안 떠서 멈췄어요. 원인은 에디터가 GIF를 처리하느라 바쁜 상태 → 재시도 3회를 기본으로 넣었습니다

공통점은 “사람이면 당연히 알아서 할 일”이 코드엔 규칙으로 적혀 있어야 한다는 거예요. 그래서 실패할 때마다 문서에 한 줄씩 추가했고, 그 문서가 LLM 위키의 한 페이지가 됐습니다.

⚠️ 6. 주의 — 시작 전에 알아둘 것

  • 내 계정, 내 콘텐츠, 사람의 속도. 자동화라고 해서 하루에 열 편씩 올리면 플랫폼이 어뷰징으로 봅니다. 저도 닷새에 40편을 내보낸 뒤 네이버 검색에서 글이 안 잡히는 걸 확인하고 하루 1편 상한을 걸었어요. 도구가 빠른 것과 빨라도 되는 건 다릅니다
  • 남의 사이트를 긁는 용도라면 약관부터. 브라우저 자동화는 강력해서, 허용되지 않은 수집이나 대량 요청은 법·약관 문제가 됩니다. 이 글의 용도는 “내 계정으로 내 글 올리기”에 한정돼요
  • 화면이 바뀌면 깨집니다. 버튼 이름이나 구조가 바뀌면 스크립트가 멈춰요. 그래서 발행 후 결과를 다시 읽는 검증 단계가 필수입니다 — AI 산출물은 검증까지가 한 세트
  • 눈에 보이는 창으로 시작하세요. 화면 없이 도는 헤드리스 모드는 나중 일이고, 처음엔 브라우저가 실제로 움직이는 걸 보면서 만드는 게 훨씬 빠릅니다

🎯 시작 코스 — 코드 10줄

파이썬이 깔려 있다면 이걸로 시작합니다. 첫 줄은 설치, 둘째 줄은 녹화기 — 브라우저에서 내가 클릭한 걸 코드로 받아 적어줍니다. 코딩을 몰라도 여기서 출발할 수 있어요.

pip install playwright && playwright install
playwright codegen https://blog.naver.com

그리고 “사람이 로그인한 창에 붙기”는 이게 전부입니다.

from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.connect_over_cdp("http://localhost:9223")  # 원격 조종 문을 열고 띄운 엣지
    page = browser.contexts[0].pages[0]                              # 사람이 로그인해둔 탭
    page.goto("https://blog.naver.com/<아이디>/postwrite")
    page.keyboard.type("안녕하세요", delay=10)                        # 사람처럼 한 글자씩
    page.screenshot(path="확인.png")                                  # 결과를 눈으로 검증

엣지는 msedge.exe --remote-debugging-port=9223 --user-data-dir=<전용 폴더>로 띄우고, 그 창에서 직접 로그인하면 준비 끝입니다. Claude Code에 “이 대본대로 네이버에 올리는 스크립트 만들어줘”라고 하면 위 코드의 나머지는 AI가 채웁니다 — 제 스크립트 37개가 그렇게 만들어졌어요.

브라우저는 세상 대부분의 일이 벌어지는 곳이고, Playwright는 그 문을 AI에게 열어주는 열쇠입니다. 다만 열쇠를 어디까지 맡길지는 사람이 정해야 해요 — 제 답은 “로그인은 사람이, 조종은 코드가”였습니다.

기준: 2026-09-10. Playwright 버전·개발사·MCP 정보는 공식 문서와 2026년 릴리스 노트 해설을 확인했습니다. 발행 건수(네이버 39·인스타 16), 스크립트 수(저장소 10·세션 27), 접속 방식 비율(붙기 39회·새 창 1회)은 이 저장소에서 직접 셌습니다. 화면은 직접 캡처, 다이어그램은 직접 제작입니다.
