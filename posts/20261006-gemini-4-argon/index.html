2026년 10월 6일 기준

이 글에는 제휴 링크가 없고 구글과 아무 관계가 없습니다. 내용은 구글 공식 블로그의 제미나이 4 아르곤 발표(2026-09-30, 영문·한국어판)와 구글 딥마인드의 페어윈드 프로그램·사이버 모델 안내 페이지 기준이며, 직접 써 본 후기는 아닙니다. 벤치마크 수치는 구글이 공개한 것입니다. 삽화는 GPT 이미지 생성, 도식은 직접 제작했습니다.

제미나이 4 아르곤(Gemini 4 Argon) 공개 — 구글 최상위 모델을 보안 방어자에게 먼저 여는 이유, 나는 언제 쓰나

솜씨 좋은 성벽 기술자를 새로 들였다고 해 볼게요. 어떤 성벽이든 금 간 곳을 금방 찾아내고 그 자리에서 메워요. 그런데 구멍을 잘 찾는 눈은, 마음만 먹으면 그 구멍으로 들어가는 길도 알아요. 그래서 처음부터 마을 사람 모두에게 보내지 않아요. 먼저 성을 지키는 수비대에 보내고, 누가 언제 불렀는지 기록하게 하고, 일하는 규칙을 다듬은 뒤에 범위를 넓히죠.

2026년 9월 30일 구글이 공개한 새 최상위 모델 제미나이 4 아르곤(Gemini 4 Argon)이 딱 이런 순서로 나왔어요. 코딩, 법률·금융 같은 전문 업무, 사이버 보안 방어에서 최상위 성능을 냈다고 발표했는데, 지금 쓸 수 있는 곳은 구글의 ‘페어윈드 프로그램’에 참여한 일부 사이버 방어자와 구글 내부 팀뿐이에요. 구글 한국어 블로그의 표현으로는 “이처럼 고도화된 프론티어 기술을 안전하게 공개하기 위해서는 단계적인 접근 방식이 필요합니다.”

⚠️ 이 글은 2026-09-30 구글 공식 블로그의 제미나이 4 아르곤 발표(영문·한국어판)와 구글 딥마인드의 페어윈드 프로그램·사이버 모델 안내 페이지를 옮긴 것입니다. 직접 써 본 후기가 아니고, 벤치마크 수치는 모두 구글이 공개한 것이에요.

결론 요약

  • 무엇 — 구글의 새 프런티어 모델이에요. 출력 한도를 6만 4천 토큰에서 100만 토큰으로 늘려 긴 작업을 한 번에 끝까지 하게 했고, 코딩·법률·금융·사이버 방어 평가에서 최상위 점수를 냈다고 밝혔어요
  • 누가 먼저 — 지금은 페어윈드 프로그램의 일부 사이버 방어자와 구글 내부 팀만 써요. 이들에게는 사이버 가드레일을 뺀 버전을 준대요. 다음은 유료 API 고객과 구글 AI 울트라 구독자, 그다음이 개발자·기업·일반 이용자예요
  • 언제·얼마 — 넓은 공개 날짜는 발표되지 않았어요. 가격은 출시 기념가로 100만 토큰당 입력 2달러, 출력 10달러로 정해 두었어요

🧭 1. 제미나이 4 아르곤은 어떤 모델인가

구글은 아르곤을 “복잡하고 장기적인 워크플로우 전반에서 깊이 있는 추론을 지속하도록 설계된” 모델이라고 소개해요. 잘한다고 내세운 분야는 세 갈래예요.

  • 실제 소프트웨어 개발 — 오래 이어지는 실전 개발 작업을 재는 DeepSWE v1.1에서 77.9%로 최고 기록을 냈대요
  • 법률·금융 같은 전문 업무 — 금융·코딩·법률·세무 업무를 미국 GDP 기여도로 가중해 재는 Vals Index에서 선두, 업무 자동화를 처음부터 끝까지 해내는지 보는 Zapier의 AutomationBench에서 51.3%로 1위라고 밝혔어요
  • 사이버 보안 방어 — 취약점을 찾고, 검증하고, 고치는 일을 스스로 해낸대요 (3장에서 자세히)

차트 분석이나 긴 영상 이해처럼 보는 능력도 내세웠어요. 긴 영상 이해를 재는 LVBench에서 91.7%로 최고 기록이래요.

구글 안에서는 이미 쓰고 있어요. 발표에 따르면 수천 명의 구글 직원이 전문 코딩, 깊은 조사, 글쓰기를 아르곤의 강점으로 꼽았고, 이런 사례를 들었어요.

  • 데이터센터 메모리 절약 — 아르곤 에이전트 팀이 서버 전체의 측정 데이터를 분석해 메모리 최적화를 스스로 찾아 적용했고, 배포 뒤 300 TiB 이상을 확보했대요. 전체 절감은 500 TiB에서 1 PiB로 예상해요
  • C/C++ 코드를 러스트(Rust)로 옮기기 — 수만 줄짜리 핵심 라이브러리부터 80만 줄이 넘는 Fuchsia의 Zircon 커널까지 옮기는 중이에요. 중요한 시스템이라 실제 운영에 넣기 전 자동·수동 감사와 테스트, 리뷰를 거치고 있대요
  • 동영상 디코더 속도 — 오픈소스 동영상 디코더 libgav1의 러스트 버전에서 SIMD 코드 3만 2천 줄을 안전한 러스트 코드로 바꿔, 같은 출력에 기존 러스트 버전보다 2.7배 빨라졌다고 해요
  • 양자 알고리즘 — 연구원들이 쓰는 계산 자원 최적화에서 기존에 발표된 기준을 몇 분 만에 40% 앞섰대요

📜 2. ‘100만 토큰’은 입력이 아니라 출력 한도

아르곤 소식에서 가장 많이 돌아다니는 숫자가 ‘100만 토큰’인데, 구글 본문을 보면 한 번에 써낼 수 있는 양(출력)이에요. 구글은 “모델의 출력 토큰 한도를 기존 6만 4천개에서 업계 최고 수준인 1백만 개로 대폭 확장했습니다”라고 적었어요. 한 번에 읽어 들일 수 있는 양(입력, 흔히 ‘컨텍스트 창’)이 얼마인지는 이번 발표에 나오지 않아요.

토큰은 AI가 글을 잘게 나눠 세는 단위예요. 출력 한도가 작으면 긴 보고서나 큰 코드 변경을 쓰다가 중간에 멈추고 “이어서 써 줘”를 반복해야 하죠. 구글은 아르곤이 “단일 실행 경로 내에서 깊이 있게 사고하고 수십만 개의 토큰을 생성할 수 있는 여유 공간”을 얻으면서, 까다로운 과제를 한 번에 풀 수 있게 됐다고 설명해요.

🛡️ 3. 사이버 방어 — 찾고, 검증하고, 고친다

구글은 아르곤을 사이버 방어에 강하도록 따로 학습시켰다고 밝혔어요. 치명적인 소프트웨어 취약점을 스스로 찾고, 검증하고, 패치할 수 있대요. 구글 딥마인드의 사이버 모델 페이지는 세 가지를 꼽아요.

  • 취약점 자율 탐지 — 복잡한 코드베이스를 돌아다니며 숨은 치명적 취약점을 찾아요
  • 모의 침투 — 소스 코드 없이 운영 중인 웹사이트와 겉으로 드러난 동작만 보고 공격 표면을 찾고, 취약점을 확인하고, 검증 근거를 만들어요
  • 자동 패치 — 취약점을 찾은 뒤 검증된 수정 코드를 자동으로 만들어요

그리고 “신뢰할 수 있는 보안 전문가 방어자들과 구글 내부 팀에는 사이버 가드레일이 적용되지 않은 버전의 아르곤이 제공될 예정”이라고 했어요. 일반 모델에 걸어 두는 사이버 관련 제한을 빼고, 방어 능력을 온전히 쓰게 한다는 뜻이에요.

구글이 든 사례와 수치는 이래요.

  • 위즈(Wiz)의 실제 사용 — 공공 인프라를 무료로 지키는 ‘스캔 포 굿’ 활동에 아르곤을 쓰고 있고, 초기 사례에서 전 세계 병원이 쓰는 헬스케어 소프트웨어에서 민감한 개인정보가 노출될 수 있는 치명적 취약점을 찾았대요. 이전 프런티어 모델들이 놓친 것이라고 해요
  • CWE-bench v1 (취약점 수정 능력) — 68%로 공동 1위예요. 구글 딥마인드 페이지 도표에서는 Grok 4.7, GPT-6 Astra가 같은 68%였어요
  • 이전 사이버 모델과 비교 — 같은 페이지 도표에서 실제 취약점 발견 85.8%(제미나이 3.8 플래시 사이버 71.0%), 위즈의 블랙박스 모의 침투 벤치마크 70.9%(58.2%)였어요. 둘 다 구글·위즈가 자체로 만든 벤치마크예요

🔐 4. 누가 먼저, 어떤 조건으로 — 페어윈드 프로그램

페어윈드 프로그램(Fairwind Program)은 구글이 2026년 9월 2일 시작한 제한 접근 프로그램이에요. 처음에는 사이버 특화 모델 제미나이 3.8 플래시 사이버와 코드 보안 에이전트 CodeMender를 정부와 신뢰할 수 있는 파트너에게 먼저 주는 프로그램이었고, 참여 파트너는 전 세계 650곳이 넘어요. 이번에 아르곤은 이 파트너 가운데 일부에게 먼저 열렸어요.

누가 들어갈 수 있나

구글은 사회의 회복력에 가장 중요한 곳부터 우선한다며 세 부류를 꼽았어요.

  • 정부와 국가 사이버 기관
  • 핵심 인프라 운영사 — 의료, 통신, 에너지, 금융망
  • 핵심 기술 플랫폼 — 수많은 사용자가 기대는 소프트웨어 기반

방어용 벤치마크를 연구하는 대학 연구실도 신청할 수 있대요. 신청은 페어윈드 페이지의 신청서로 하고, 구글은 기준에 맞는 곳에 “가능한 한 빨리” 답하겠다고만 했어요. 신청한 기관은 보안 이력과 윤리적 운영 기록을 확인받아요.

참여 기관이 지키는 조건

  • 사용자 단위 인증, 피싱 방지 다단계 인증(MFA), 접근 통제
  • 아르곤은 사내 보안·사고 대응·모의 침투 팀에게만 줄 수 있고, 직원의 접근과 사용을 기록해야 해요
  • 허용된 이중용도 작업만 — 승인된 위협 시뮬레이션, 역공학, 악성코드 분석 같은 방어·학술 목적이에요. 악성코드 만들기 같은 일은 금지예요
  • 받은 접근을 다른 곳에 공유·재배포·판매할 수 없어요

대상이 아니라면

구글은 페어윈드 대상이 아닌 조직도 공개된 모델로 CodeMender를 써서 코드를 지킬 수 있다고 안내해요. 학생은 구글 클라우드에서 CodeMender를 쓰라고 권하고요.

🧯 5. 넓게 풀기 전에 강화하는 안전장치 4가지

구글은 넓은 공개에 앞서 네 영역을 계속 강화하고 있다고 밝혔어요. 그사이 미국 정부의 자발적인 ‘사전 출시 모델 접근’ 절차에도 참여하고 있대요.

  • 오용 막기 — 사이버 공격이나 화학·생물·방사능·핵(CBRN) 공격에 쓰이지 않도록 해로운 요청은 거절하고, 정당한 이중용도 연구는 돕도록 설계했대요. 모델 내부 신호를 지켜보며 오용 징후를 잡는 기술을 높였고, 내부·외부 레드팀이 수동·자동 공격으로 시험했어요
  • 프롬프트 인젝션 막기 — 문서나 웹페이지에 숨긴 악성 지시로 모델을 조종하는 공격에 대해 구글 모델 중 가장 강하대요. Gray Swan의 간접 프롬프트 인젝션 벤치마크에서 선두이고, 딥마인드 페이지 도표에서는 15번 시도 기준 공격 성공률이 0.7%로 비교 모델 중 가장 낮았어요
  • 목표 이탈 감시 — 사용자 의도를 넘어선 방식으로 일을 끝내려 하지 않도록, 아르곤의 추론 과정과 행동을 지켜보다가 필요하면 실행을 멈춰요. 학습 과정도 비슷한 장치로 지켜봤는데, 거기서 나온 결과는 다시 학습에 넣지 않도록 주의했대요. 감시를 피하는 쪽으로 추론이 길들여질 수 있어서예요
  • 시험 환경 잠그기 — 위험도가 높은 학습·평가 전에는 샌드박스를 격리하고 봉인해요

🎟️ 6. 나는 언제, 얼마에 쓸 수 있나

  • 지금 — 페어윈드 프로그램의 일부 사이버 방어자와 구글 내부 팀만 써요. 10월 6일 현재 Gemini API의 모델·가격 안내 페이지에도 아르곤은 아직 없어요
  • 다음 — 유료 API 고객과 구글 AI 울트라 구독자부터 열고, 이어서 개발자·기업·일반 이용자로 넓힌대요. 구글은 “조속히”, “가능한 한 빨리”라고만 했고 날짜는 밝히지 않았어요. 한국 제공 여부나 시점도 발표에 없어요
  • 가격 — 출시 기념가로 100만 토큰당 입력 2달러, 출력 10달러, 캐시된 입력은 입력 가격에서 95% 할인이에요. 기념 기간이 끝나면 입력 4달러, 출력 20달러가 적용돼요. 기념 기간이 언제까지인지는 나오지 않았어요
  • 조직이라면 — 정부·핵심 인프라·핵심 기술 플랫폼에 해당하면 페어윈드 신청을 검토할 수 있어요. 아니라면 공개 모델로 CodeMender를 쓰는 길이 안내돼 있어요

🎯 7. 무슨 뜻인가 — 도입·교육 관점

9월 첫 주에는 AI 회사들이 사이버 특화 기능에 문을 걸었어요(AI 3사가 해킹 능력 모델의 문을 잠근 이야기). 이번에는 구글의 최상위 범용 모델 자체가 검증된 방어자부터 열렸어요. 코딩·법률·금융까지 잘한다고 내세운 모델이 첫날 일반 공개 대신 ‘자격을 확인한 곳 먼저’로 나온 거예요.

happy_various는 이걸 이렇게 봐요. 프런티어 모델 공개 방식이 ‘전면 출시’에서 ‘단계 공개’로 바뀌고 있고, 그래서 AI 도입 교육에도 권한 검증 설계가 들어가야 하는 시대가 왔다고요.

  • ‘무엇을 쓰나’보다 ‘누가 어떤 권한으로 쓰나’ — 최신 모델을 먼저 받을 수 있는지가 조직의 자격과 통제 체계에 달리기 시작했어요. 도입 교육도 모델 사용법만큼, 누가 어떤 계정과 권한으로 쓰고 무엇을 남기는지를 앞에 두는 게 맞다고 봐요
  • 페어윈드 조건은 그대로 점검표가 된다 — 사용자 단위 인증, 피싱 방지 MFA, 사용 팀 제한, 접근·사용 기록, 허용 작업의 범위. 구글이 참여 기관에 요구한 이 항목들은 어느 조직이든 AI 도구를 들일 때 미리 갖춰 둘 만한 기본기라고 봐요. 이런 기본기를 갖춘 조직이 다음 단계 공개에서도 덜 기다릴 거라는 게 happy_various의 생각이에요
  • 발표 숫자는 발표 숫자로 — 이번 수치는 전부 구글이 공개한 것이고, 일부는 구글·위즈가 자체로 만든 벤치마크예요. 교육에서 모델을 비교할 때도 ‘누가 잰 숫자인지’를 같이 적는 습관이 필요해 보여요
