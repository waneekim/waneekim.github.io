클로드 코드 서브에이전트 사용법, 언제 쓰고 어떻게 만드나

클로드 코드 서브에이전트 사용법 — 큰 일은 나눠 맡기고 결론만 받기 (캐릭터는 GPT 이미지 생성)

클로드 코드에 큰 조사를 시키면 이런 순간이 와요. “코드 전체에서 이 함수 쓰는 곳 다 찾아줘.” 파일을 수십 개 읽는 사이 대화창이 무거워지고, 정작 하려던 작업의 맥락이 흐려져요.

팀장이 자료 조사를 팀원에게 맡기는 장면을 떠올려 보세요. 팀원은 자기 책상에 서류를 잔뜩 펼쳐 놓고 찾고, 팀장 책상에는 한 장짜리 보고서만 올라와요. 서브에이전트(subagent)가 바로 이 팀원이에요.
서브에이전트는 일을 나누는 기능이기 전에, 맥락을 나누는 기능이에요.

팀원이 서류 더미는 자기 책상에 두고 보고서 한 장만 건네는 장면 — 서브에이전트를 빗댄 그림 (GPT 이미지 생성)

준비물: 클로드 코드 · 작업할 프로젝트 폴더
2026년 10월 기준 · Windows 11 · 2.1.268

1. 맥락을 따로 쓰는 보조 일꾼

서브에이전트는 메인 대화와 분리된 자기 맥락 창에서 일하고, 결과만 돌려주는 보조 일꾼이에요. 공식 문서는 검색 결과·로그·파일 내용처럼 다시 볼 일 없는 것이 메인 대화를 채울 때 쓰라고 해요. 서브에이전트가 그 일을 자기 맥락에서 하고 요약만 돌려줘요.

그래서 서브에이전트가 파일을 백 개 읽어도, 내 대화에는 결론만 남아요. 대화가 길수록 요청마다 쓰는 양이 커지는 문제를 피하는 길이기도 해요. 일을 나누는 게 아니라 맥락을 나누는 것, 이게 핵심이에요.

서브에이전트 구조 — 메인 대화가 맡기고, 서브에이전트가 따로 조사하고, 결론만 돌아온다 (직접 제작)

2. 언제 쓰나: 세 가지 상황

파일을 많이 읽어야 답이 나오는 일, 서로 상관없는 여러 일, 같은 역할을 되풀이하는 일에 맞아요.

상황예
큰 탐색·조사이 함수가 쓰이는 곳 전부 찾기 — 결론만 필요할 때
나눠서 동시에폴더 세 곳을 세 서브에이전트가 동시에 조사
역할 고정코드 리뷰어·테스트 작성자처럼 한 관점으로만

공식 문서도 서로 독립된 조사는 서브에이전트 여러 개를 동시에 돌리라고 해요. 저는 블로그 글감 조사를 여러 각도로 나눠 동시에 돌릴 때 이렇게 써요.

세 일꾼이 각자 책상에서 동시에 자료를 찾는 장면 — 서브에이전트를 동시에 돌리는 것을 빗댄 그림 (GPT 이미지 생성)

3. 말로 맡기기

따로 만들지 않아도 돼요. 요청에 서브에이전트로 해 달라고 적으면, 클로드 코드가 판단해서 맡겨요. 클로드 코드에는 서브에이전트가 이미 들어 있어요. 코드를 읽기만 하며 찾는 Explore, 계획 모드에서 자료를 모으는 Plan, 찾고 고치는 일을 다 하는 general-purpose예요.

❌ 이렇게 말고

이 함수 어디서 쓰이는지 찾아줘

무엇을 돌려받을지가 빠져 있어요. 결과가 길게 오면 그만큼 내 대화가 무거워져요.

⭕ 이렇게

서브에이전트로 이 함수가 쓰이는 곳을 전부 찾고, 파일 이름과 한 줄 설명만 돌려줘

맡기면 대화 기록에 서브에이전트 이름과 짧은 작업 설명이 한 줄로 보여요. 서브에이전트는 메인 대화 기록을 보지 못하고 새로 시작해요. 그래서 배경과 범위, 돌려받을 모양을 요청에 적어 주는 게 중요해요.

💡 핵심맡길 때는 무엇을 찾을지와 무엇만 돌려받을지를 같이 적으세요.

4. 내 서브에이전트 만들기

자주 맡기는 역할은 파일 하나로 만들어 두면, 이름으로 부르거나 클로드 코드가 알아서 불러요. 만드는 법은 클로드에게 말로 부탁하는 게 가장 쉬워요.

예전 글에서는 /agents로 만든다고 썼는데, 2.1.268에서는 /agents가 만들기 화면을 열지 않아요. 공식 문서에 따르면 2.1.197까지는 만들기 화면이 열렸고, 지금은 클로드에게 부탁하거나 .claude/agents/ 폴더의 파일을 직접 고치라는 안내만 보여 줘요. 아래는 공식 문서의 방법이에요.

📋 그대로 복사해 쓰세요

이 프로젝트의 .claude/agents/ 폴더에 읽기만 하는 code-reviewer 서브에이전트를 만들어줘. 코드 품질을 검토하고 sonnet 모델을 쓰게 해줘
  1. 위 요청을 클로드 코드에 입력하세요.→ .claude/agents/code-reviewer.md 파일이 생겨요.
  2. 파일을 열어 맨 위 설정을 확인하세요.→ 이름·설명·도구·모델이 아래와 같은 모양으로 적혀 있어요. 그 아래 줄은 서브에이전트가 받는 지시문이에요.
---
name: code-reviewer
description: Reviews code quality
tools: Read, Glob, Grep
model: sonnet
---

네 항목이 정하는 것을 표로 정리했어요.

항목정하는 것
name부를 때 쓰는 이름
description언제 맡길지 — 클로드 코드가 이걸 보고 알아서 맡겨요
tools쓸 수 있는 도구 — 조사용은 읽기·검색만
modelsonnet·opus·haiku 같은 별칭, 또는 inherit(메인과 같게)

파일을 .claude/agents/에 두면 그 프로젝트에서만 쓰고, 저장소에 올려 팀과 나눠요. ~/.claude/agents/에 두면 내 모든 프로젝트에서 써요. 이름이 같으면 프로젝트 쪽이 먼저예요. 쓸 때는 이름을 불러요. 꼭 그 서브에이전트가 돌게 하려면 @를 치고 목록에서 고르세요.

code-reviewer 서브에이전트로 오늘 바꾼 파일을 검토해줘

5. 훅과 뭐가 다른가

훅은 정해진 시점에 무조건 실행되는 규칙이고, 서브에이전트는 필요할 때 일을 떼어 맡기는 일꾼이에요.
훅(hooks) — 내가 시스템에 거는 강제예요. AI가 고르지 않아도 그 시점이 오면 반드시 돌아요.
서브에이전트 — 판단해서 맡기는 위임이에요. 언제 맡길지는 내 요청과 description이 정해요.

강제해야 하면 훅, 나눠 맡기고 싶으면 서브에이전트라고 기억하면 돼요.

6. 쓰지 않는 게 나은 때

작고 빠른 일, 주고받기가 많은 일은 메인 대화에서 하는 게 나아요. 공식 문서가 메인 대화를 권하는 경우는 넷이에요.
① 여러 번 주고받으며 다듬어야 하는 일
② 계획·구현·테스트처럼 단계끼리 맥락을 많이 나누는 일
③ 파일 한두 개를 고치는 빠르고 좁은 수정
④ 답이 빨리 필요할 때 — 서브에이전트는 새로 시작해서 맥락을 모으는 데 시간이 걸려요

위임한 일은 과정이 보이지 않고 결론만 와요. 중요한 작업은 그 결론을 다시 확인하세요.

⚠️ 주의서브에이전트도 따로 요청을 보내서 같은 사용량 한도를 써요. 여러 개를 한꺼번에 돌리면 한도가 빨리 닳아요.

막힐 때

/agents를 입력해도 만들기 화면이 안 떠요
원인: 2.1.197보다 새 버전에서는 /agents가 안내만 보여 줘요.
해결: 4번처럼 클로드에게 말로 부탁하거나, .claude/agents/ 폴더에 파일을 직접 만드세요.

새로 만든 서브에이전트를 못 찾아요
원인: 세션을 켤 때 ~/.claude/agents 폴더가 없었으면, 켜져 있는 세션은 새로 생긴 폴더를 알아채지 못해요.
해결: 클로드 코드를 다시 켜고 다시 부르세요.

서브에이전트 결과가 엉뚱해요
원인: 서브에이전트는 메인 대화 기록을 보지 못하고 새로 시작해요.
해결: 배경, 찾을 범위, 돌려받을 모양을 요청에 적으세요.

자주 묻는 질문

Q. 서브에이전트를 꼭 만들어야 쓸 수 있나요?

아니요. Explore 같은 기본 서브에이전트가 들어 있어서, 요청에 서브에이전트로 해 달라고 적으면 돼요. 자주 쓰는 역할만 파일로 만들어 두세요.

Q. 서브에이전트를 쓰면 한도를 더 쓰나요?

네. 서브에이전트마다 요청을 따로 보내고, 메인 대화와 같은 한도에서 빠져요. 가벼운 일은 model에 haiku처럼 작은 모델을 지정하면 덜 써요.

Q. 서브에이전트가 또 서브에이전트를 부를 수 있나요?

네. 공식 문서에 따르면 기본으로 메인 대화 아래 세 단계까지 부를 수 있어요.
