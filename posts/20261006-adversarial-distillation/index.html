적대적 증류 뜻, OpenAI·앤트로픽이 막은 AI 풀이 과정 빼내기

적대적 증류 뜻과 대응 — OpenAI·앤트로픽이 막은 풀이 과정 빼내기 (캐릭터는 GPT 이미지 생성)

AI 회사들이 ‘증류 공격’을 막았다는 소식이 연달아 나왔어요. 읽다 보면 이런 질문이 남아요. “증류가 뭐고, AI를 쓰기만 하는 우리 회사와는 무슨 상관이지?”

유명 일타강사의 수업을 떠올려 볼게요. 같은 학원이 그 강의로 짧은 ‘요약 강좌’를 만드는 건 흔한 일이에요. 그런데 다른 학원이 가짜 이름으로 수강생 수천 명을 등록시켜, 강사의 답과 풀이 과정을 통째로 받아 적은 뒤 자기 교재로 쓴다면 이야기가 달라지죠.
AI에서는 앞의 것을 증류, 뒤의 것을 적대적 증류라고 불러요. 남의 AI가 내놓은 답과 풀이 과정을 허락 없이 대량으로 받아 내 모델을 키우는 행위예요.

⚠️ 출처 안내OpenAI(9월 30일)·앤트로픽(2월 23일, 9월 10일)·구글(2월 13일) 공식 발표를 옮긴 글이에요. 지목된 회사와 수치는 각 회사의 발표이고, 지목된 회사들의 입장은 확인하지 않았어요. 공격 방법은 큰 흐름만 적었어요.

칠판에 풀이를 쓰는 로봇 선생님과, 변장하고 몰래 받아 적는 똑같은 학생들 — 적대적 증류를 학원에 빗댄 그림 (GPT 이미지 생성)

1. 뜻: 선생 모델과 학생 모델

증류 자체는 정상적인 학습 방법이에요. 문제는 허락 없이 남의 모델을 선생으로 쓰는 거예요. 앤트로픽 설명으로는 더 크고 뛰어난 ‘선생’ 모델이 만든 답으로, 더 작은 ‘학생’ 모델이 선생을 흉내 내도록 훈련하는 방법이에요.

AI 회사들도 자기 모델을 증류해 작고 저렴한 버전을 만들고, 구글은 클라우드에서 증류 기능을 상품으로도 제공해요.

무단 증류를 부르는 말은 회사마다 조금씩 달라요.

회사·용어뜻
OpenAI · 적대적 증류한 모델의 출력이나 추론을 체계적으로 무단 사용해 다른 모델의 학습·재현·개선에 쓰는 것
앤트로픽 · 불법 증류모델 능력을 허가 없이 빼내 다른 모델에 옮기는 산업 규모의 은밀한 활동
구글 · 모델 추출 공격정당한 접근으로 모델을 체계적으로 찔러 보고, 얻은 정보로 새 모델을 학습시키는 것

세 회사 모두 이런 무단 증류를 이용 약관 위반으로 봐요.

특히 노리는 건 답보다 ‘풀이 과정’이에요. 요즘 AI는 답을 내기 전에 속으로 풀이를 거쳐요. OpenAI는 이를 ‘보호된 추론’이라 부르며 “모델이 작업을 수행하는 과정의 내부 기록”이라고 설명해요. 이걸 빼내면 최종 답에서 빠진 정보가 드러나고, 다른 곳이 그 능력을 재현하는 데 도움이 된대요. 학원 비유로 치면 칠판의 답보다 강사의 풀이 노트가 더 탐나는 셈이에요.

두 회사의 걱정도 같아요. 빼낸 추론으로 키운 모델에는 원래 모델의 안전장치가 따라가지 않아요. OpenAI와 앤트로픽 모두 이 점을 짚었어요.

적대적 증류의 흐름 — 가짜 계정, 대량 질문, 답·추론 수집, 학생 모델 학습과 회사들이 막은 곳 (직접 제작)

2. OpenAI가 막은 것 (9월 30일)

OpenAI는 자사 모델의 보호된 추론을 빼내려던 조직적인 활동을 적발해 7월 28일 완전히 막았다고 발표했어요. 발표에 나온 흐름을 날짜순으로 옮기면 이래요.
① 7월 1일 — 활동 시작, 처음엔 소규모
② 7월 24·25일 — 4,000명이 넘는 사용자가 추출 패턴을 쓴 요청 16,000건을 보냈어요. OpenAI는 이 숫자가 시도 횟수이며 성공했다는 뜻은 아니라고 적었어요
③ 추가 조사 — 15,000명이 넘는 사용자 집단에서 관련 패턴을 확인
④ 7월 28일 — 완전 차단

OpenAI는 공격자들이 암호화를 해독하거나 데이터베이스를 침해한 게 아니고, 저장된 사용자 대화에 접근한 것도 아니라고 밝혔어요. 대화를 조작해 감춰진 추론이 요청자에게 보이게 하려 했다고 해요. 모든 공격자가 한 주체인지는 불분명하다면서도, 핵심 활동 집단을 Kimi 개발사 Moonshot AI와 연관된 개인들로 판단했어요.

막은 방법은 네 갈래예요. 부정 계정 차단·제한과 가입 통제 강화, 다른 사용자의 암호화된 추론을 되살릴 수 있던 경로 차단, 추론이 드러날 수 있는 출력의 전송 보류, 프런티어 모델 포럼과 정부 정보 공유 채널을 통한 정보 공유예요.

3. 앤트로픽이 밝힌 것 (2월·9월)

앤트로픽은 2월에 3곳, 9월에 중국 기반 연구소 7곳의 증류 공격을 적발·차단했다고 밝혔어요. 2월 23일 첫 공개에서는 DeepSeek·Moonshot·MiniMax가 약 2만 4,000개의 부정 계정으로 Claude와 1,600만 건이 넘는 대화를 주고받았다고 했어요.

9월 10일 위협 보고서는 2월 이후 7곳을 추가로 적발했다며, 특정 연구소의 소행으로 ‘높은 확신’을 갖고 판단했다고 적었어요. 보고서가 지목한 곳은 이래요.

지목된 곳앤트로픽 발표 내용과 관측 규모
알리바바(Qwen)Opus의 풀이 과정을 모아 Qwen 학습에 사용. 5월부터 7월까지 1억 5,100만 건 이상
문샷 AI(Kimi)고객 요청 일부를 알리지 않고 Claude로 넘겨 추론을 뽑음. 5월부터 7월까지 2,300만 건 이상
딥시크문샷과 비슷한 방식. 7월 중 14일간 1,210만 건 이상
즈푸(Z.ai)부정 계정 273개로 추론을 모아 학습용으로 정제. 6·7월 중 17일간 340만 건 이상
샤오미자사 모델 사용자의 대화를 Claude에 다시 돌림. 3·4월 중 20일간 40만 건 이상
센스타임제3자 데이터 판매자에게서 Claude 대화 기록을 사들임. 규모 미공개
미니맥스관계를 숨긴 회사로 자체 중계 서비스 운영. 규모 미공개

통로는 ‘중계소’와 도난 API 키였어요. 앤트로픽에 따르면 이 연구소들은 주로 ‘중계소’(transfer stations)라 불리는 프록시 서비스로 Claude에 접속했어요. 이 서비스들은 가짜 신원, 가짜·도난 신용카드, 도난 API 키로 계정을 수천 개씩 만들었고, 정상 회사나 개인에게서 훔친 API 자격 증명을 쓰는 경우도 많았대요.

사용자 데이터도 문제였어요. 중계 서비스가 사용자 몰래 대화를 저장해 팔기도 했고, 그렇게 넘어간 대화에는 이름, 이메일 주소, 회사 데이터, 실제로 쓰이는 접속 비밀번호가 들어 있었다고 해요.

돋보기를 든 경비 로봇이 변장한 줄은 막고, 사원증 단 고객은 초록 통로로 보내는 장면 (GPT 이미지 생성)

앤트로픽이 밝힌 대응은 이래요.
① 이상 신호로 중계 네트워크 계정을 찾아, 한 계정씩이 아니라 배후 조직 단위로 묶어 조치
② 추출 시도만 잡는 전용 분류기로 요청을 막고 계정을 정지
③ 응답 전에 추론을 요약하고 암호화해서, 빼낸 기록이 학습에 덜 쓸모 있게
④ 무단 재판매나 지원하지 않는 국가에서 운영되는 계정 같은 신호가 보이면 신원 확인을 요구하고, 못 하면 정지

4. 구글도 먼저 겪었다 (2월)

구글 위협 인텔리전스 그룹(GTIG)은 2월 13일 보고서에서 Gemini를 노린 모델 추출 시도가 늘었다고 밝혔어요. 한 사례에서는 10만 건이 넘는 프롬프트로 Gemini의 추론 과정을 통째로 꺼내려 했는데, 구글 시스템이 실시간으로 알아채 위험을 낮췄대요.

정부 배후 해킹 조직(APT)이 프런티어 모델을 직접 공격한 사례는 관측하지 못했고, 전 세계 민간 기업과 연구자들의 추출 시도를 자주 막았다고 했어요.

구글 보고서에서 눈여겨볼 문장은 두 개예요.
① 모델 추출·증류 공격은 보통 일반 사용자에게 위험이 되지 않고, 위험은 모델 개발사와 서비스 제공자에게 몰린다
② AI 모델을 서비스로 제공하는 조직은 API 접근에서 추출·증류 패턴을 모니터링해야 한다

5. AI API를 쓰는 조직이 점검할 것

세 회사 발표에서 ‘이용하는 쪽’이 챙길 부분을 골라 점검표로 묶었어요. 회사들이 낸 공식 체크리스트가 아니라, 발표 내용을 바탕으로 이 글이 정리한 거예요.

API 키는 사원증처럼 관리해요. 앤트로픽 보고서에서 가장 마음에 걸리는 건 정상 회사의 도난 API 키가 통로로 쓰였다는 점이에요.
① 키마다 담당자와 용도를 정하고, 어디에 보관돼 있는지 목록으로 알고 있기
② 코드 저장소·문서·메신저·프롬프트에 키를 붙여 넣지 않기
③ 퇴사, 프로젝트 종료, 유출 의심 때 바로 폐기하고 새로 발급하기

💡 핵심우리 회사의 API 키가 남의 증류 공격 통로가 될 수 있어요. 키마다 담당자·보관 위치·폐기 시점을 정해 두세요.

사용량은 평소와 다른 급증에 알림을 걸어요. 앤트로픽은 좁은 능력에 몰린 엄청난 양과 아주 반복적인 구조를 증류 공격의 특징으로 꼽았어요.
① 월 예산 한도와 사용량 알림을 걸어 두기
② 키별·프로젝트별 사용량을 나눠 보고, 평소와 다른 급증이나 쓰지 않는 시간대의 호출 확인하기
③ 자체 AI 기능을 외부에 API로 제공한다면, 구글 말대로 우리도 추출 패턴을 지켜보는 쪽이 된다는 점 기억하기

경로와 약관도 확인해요.
① 공식 판매 경로인지 확인하기 — 값싼 비공식 중계 서비스는 대화를 몰래 저장해 팔기도 했어요
② 프롬프트에 비밀번호·고객 정보를 넣지 않기 — 중계로 넘어간 대화에 실제 접속 비밀번호와 회사 데이터가 있었어요
③ AI 출력물로 사내 모델을 학습시킬 계획이면, 그 쓰임을 서비스 약관이 허용하는지 먼저 확인하기. 판단이 애매하면 법무 검토를 거치는 게 안전해요

6. 무슨 뜻인가: 도입·교육 관점

이번 발표들에서 눈에 띄는 건 공격 기술보다 통로예요. 가짜 계정, 도난 카드, 정상 회사에서 새어 나간 API 키, 대화를 몰래 저장하는 중계 서비스. 모두 AI를 ‘쓰는 쪽’의 관리와 맞닿아 있어요.

그래서 저는 AI 도입 교육에 API 보안 항목을 기본으로 넣어야 할 이유가 또렷해졌다고 봐요. 지금까지 도입 교육은 프롬프트 잘 쓰는 법과 업무 활용 사례가 중심이었죠. 여기에 세 가지 질문을 첫 시간부터 같이 다루면 좋겠어요.
① 키는 누가 어디에 두는가
② 사용량은 누가 보는가
③ 출력물은 어디까지 써도 되는가

모델 회사들이 계정 인증과 신원 확인을 계속 강화하고 있으니, 정상 고객도 그 흐름에 맞춰 준비해 둘수록 덜 당황할 거예요.
