이 글에는 제휴 링크가 없고 OpenAI·앤트로픽·구글과 아무 관계가 없습니다. 제가 직접 만든 중계기의 개발 기록을 바탕으로 썼습니다. 삽화는 GPT 이미지 생성, 도식은 직접 제작했습니다.

LLM 게이트웨이 구조, 질문 하나가 지나가는 네 칸과 두 창구 (LLM 중계기 개발기)

LLM 게이트웨이 구조 — 질문 하나가 지나가는 네 칸과 두 창구 (캐릭터는 GPT 이미지 생성)

“주소 한 줄만 바꾸면 여러 AI를 쓸 수 있다는데, 그 주소 안에서는 무슨 일이 일어날까?” 1편을 읽고 이런 궁금증이 남았을 거예요.

해외여행 가방에 꼭 챙기는 물건이 있죠. 여행용 멀티 어댑터예요. 나라마다 콘센트 구멍 모양이 다른데, 이 작은 상자 하나만 있으면 내 충전기를 어디에든 꽂을 수 있어요. 겉으로는 플러그 덩어리 하나지만 안에서는 하는 일이 나뉘어 있어요. 충전기를 받아 주는 구멍, 나라별 모양으로 바꿔 주는 부품, 제품에 따라서는 전기가 한꺼번에 너무 많이 흐르지 않게 막는 장치도 들어 있어요.
제가 만든 LLM 중계기도 뚜껑을 열면 칸 네 개와 창구 두 개로 나뉘어 있어요.

이 글은 ‘LLM 중계기 개발기’의 2편이에요. 1편에서는 여러 AI를 주소 하나 뒤에 세우는 중계기를 왜 만들었는지 이야기했어요. 오늘은 그 중계기의 뚜껑을 열어 안에서 무슨 일이 일어나는지 들여다볼게요.

공항에서 멀티 어댑터를 들어 보이는 로봇 — 중계기를 여행용 어댑터에 빗댄 그림 (GPT 이미지 생성)

2026년 10월 1일 기준 · 중계기 v0.1.108

1. 질문 하나가 지나가는 네 칸

프로그램이 보낸 질문은 창구 → 교통정리 → 어댑터를 지나 AI에 닿고, 답은 흘려보내기 칸을 지나 돌아와요. 1편에서 프로그램 쪽이 할 일은 “AI 주소를 중계기 주소로 바꾸는 한 줄”이 전부라고 했어요. 그 주소로 들어간 질문이 지나는 칸이 넷이고, 실제 프로그램 파일도 이 칸대로 나뉘어 있어요.

칸하는 일
① 창구질문을 받아 형식을 확인하고 보낼 AI를 정해요
② 교통정리바로 보낼지, 줄을 세워 기다리게 할지 정해요
③ 어댑터질문을 그 AI가 알아듣는 방식으로 바꿔요
④ 흘려보내기AI가 쓰는 답을 오는 대로 바로 넘겨요

LLM 게이트웨이 구조 — 질문 하나가 창구·교통정리·어댑터를 지나 AI에 닿고 답이 조금씩 돌아오는 길, 그리고 두 창구 (직접 제작)

여행용 어댑터에 빗대면 ①은 충전기를 꽂는 구멍, ②는 과부하를 막는 장치, ③은 나라별 모양으로 바꾸는 부품이에요.
④는 전기 어댑터에는 없는 칸인데, AI가 답하는 방식 때문에 필요해졌어요.

2. 창구와 교통정리, 받고 차례를 정한다

창구는 질문을 맨 먼저 받아 보낼 곳을 정하고, 보낼 수 없으면 이유를 담아 돌려보내요. 프로그램은 claude/opus처럼 ‘AI 이름/모델 이름’ 모양으로 누구에게 물을지 적어 보내요. 창구는 이 이름을 보고 보낼 곳을 정해요.

보낼 수 없는 질문이면 프로그램이 알아들을 수 있는 이유를 담아 그 자리에서 돌려줘요.
① 그 AI는 아직 열쇠를 넣지 않았거나 로그인하지 않았다
② 그런 모델은 없다
③ 질문이 너무 크다

1편에서 프로그램마다 다시 만들어야 했던 ‘오류 정리’를 이 칸이 한 번에 맡는 셈이에요.

교통정리는 AI마다 한꺼번에 받을 수 있는 질문 수를 지켜요. 제 중계기는 기본 설정에서 Codex와 Claude에 각각 동시에 3건까지, 같은 모델에는 한 번에 1건씩만 보내요.

자리가 없으면 질문은 줄을 서서 차례를 기다려요. 줄이 너무 길거나 너무 오래 기다리면 “지금은 붐빈다”고 알려 주며 돌려보내요. 교통정리가 왜 그렇게 중요한지는 3부에서 따로 다룰게요.

3. 어댑터와 흘려보내기

어댑터는 AI마다 하나씩 있어서, 공통 질문을 그 AI의 말로 바꿔 전달하고 답을 다시 공통 모양으로 바꿔요. Codex와 Claude는 원래 사람이 터미널에서 쓰는 명령어 도구이고, 다른 AI는 인터넷 너머의 주소에 열쇠(API 키)를 보여 주고 부르는 방식이에요. 부르는 방법도, 답을 돌려주는 모양도 제각각이에요.

그래서 새 AI를 붙이려면 어댑터 파일 하나를 만들고 목록에 한 줄만 등록하면 돼요. 어댑터가 지켜야 하는 약속은 2부에서 자세히 이야기할게요.

💡 핵심새 AI를 붙일 때 바뀌는 건 어댑터 하나예요. 창구·교통정리·흘려보내기는 그대로 써요.

어댑터를 실제로 돌리는 부분은 옆에서 스톱워치와 장부를 들고 있어요. 첫 글자가 오기까지 걸린 시간, 쓴 토큰, 답이 끝난 이유를 적어 둬요.

AI는 답을 한 번에 주지 않고 한 조각씩 써 내려가서, 중계기도 조각이 오는 대로 바로 넘겨요. 채팅 화면에서 답이 타자 치듯 나타나는 게 그 때문이에요. 이런 방식을 스트리밍이라고 불러요.

AI가 오래 생각하느라 한동안 아무 글자도 보내지 않을 때도 있어요. 그러면 프로그램은 연결이 끊긴 건지 헷갈리겠죠. 그래서 중계기는 답을 기다리는 동안 15초마다 “아직 연결돼 있어요” 신호를 따로 보내요.

4. 창구는 두 개, 사람용과 프로그램용

중계기에는 프로그램이 질문을 보내는 API 창구 말고, 사람이 보는 관리 화면이 하나 더 있어요. API 창구는 1편에서 말한 ‘OpenAI 호환’ 형식을 쓰고, 관리 화면에서는 아래 네 가지 일을 해요.

사람용 창구와 프로그램용 창구를 함께 맡은 로봇 접수원 (GPT 이미지 생성)

① AI 연결 — 열쇠로 쓰는 AI는 열쇠를 넣고 연결하면, 그 열쇠가 실제로 통하는지 AI 쪽에 확인해요
② 진단 — Codex·Claude는 설치, 로그인, 실제 호출 한 번을 차례로 확인하고, 막힌 단계에 맞는 안내를 띄워요
③ 스위치 — 프로그램용 API 창구를 열고 닫아요. 꺼 두어도 관리 화면과 연결 설정은 그대로 동작해요
④ 기록 — 요청마다 기록이 한 줄씩 쌓여요(5번에서 설명)

API 창구는 처음 실행할 때 꺼진 채로 시작해요.
8월 12일 업데이트(v0.1.67)부터 그렇게 바꿨어요. 막 설치한 중계기에는 연결된 AI가 하나도 없어서, 창구를 열어 봐야 빈 목록만 보여 줄 테니까요. AI를 연결하고 스위치를 켜면 되고, 그다음부터는 마지막에 켜 뒀는지 꺼 뒀는지를 기억해 그대로 돌려놓아요. 이미 쓰고 있던 중계기는 원래처럼 켜진 채로 시작하게 남겨 두었어요. 보여 줄 게 없으면 창구를 열지 않는다는 게 그때 정한 기본값이에요.

5. 기록 한 줄에 담기는 것

답이 끝날 때마다 관리 화면에 기록이 한 줄 남고, 거기에 다섯 가지가 적혀요.

기록뜻
토큰 (질문 → 답, 합계)AI가 글을 잘게 나눠 세는 단위 — 질문과 답에 각각 몇 개를 썼는지
첫 글자까지 걸린 시간질문을 보내고 답의 첫 조각이 오기까지. 흔히 TTFT라고 불러요
줄 선 시간교통정리 칸에서 차례를 기다린 시간(기다렸을 때만)
전체 시간질문을 보낸 때부터 답이 끝날 때까지
끝난 이유스스로 끝났는지, 정해 둔 길이를 다 써서 잘렸는지

끝난 이유가 ‘길이를 다 써서 잘림’이면 그 줄은 경고로 표시돼요. 겉보기엔 멀쩡히 끝난 답이 사실은 중간에 잘린 것일 수 있거든요. 이 이야기는 4부에서 다시 꺼낼게요.

6. 처음부터 지키는 세 가지

여러 AI의 열쇠를 한곳에 모아 두는 프로그램이라, 처음부터 세 가지를 기본값으로 정해 두었어요.

작은 열쇠를 금고에 조심스럽게 넣는 로봇 — 열쇠는 암호화해 내 컴퓨터에만 (GPT 이미지 생성)

① 내 컴퓨터 안에서만 열린다 — 관리 화면도 API 창구도 내 컴퓨터 안에서만 접속할 수 있어요. 같은 와이파이의 다른 기기나 인터넷에서는 들어올 수 없어요.

② 열쇠는 암호화해서 내 컴퓨터에만 둔다 — 넣은 API 키는 저장하는 순간 암호화돼(AES-256-GCM이라는 널리 쓰이는 방식) 내 컴퓨터의 파일 하나에만 남고, 다른 곳으로 보내지 않아요. Codex·Claude는 원래 쓰던 로그인을 그대로 써요.

③ 기록에는 열쇠와 질문 내용을 남기지 않는다 — 모델 이름, 메시지 개수, 토큰 수, 시간 같은 정보만 남겨요. 오류 메시지에 열쇠가 섞여 나오면 앞 세 글자만 남기고 가려요.

✅ 한눈에 정리① 질문은 창구 → 교통정리 → 어댑터를 지나요
② 답은 오는 대로 조금씩 흘려 돌려줘요
③ 창구는 관리 화면과 API 두 개, API는 처음엔 꺼짐
④ 내 컴퓨터 안에서만, 열쇠는 암호화, 기록엔 질문 없음

자주 묻는 질문

Q. 중계기를 켜 두면 다른 기기에서도 쓸 수 있나요?

아니요. 관리 화면도 API 창구도 내 컴퓨터 안에서만 접속되게 묶어 두었어요. 같은 와이파이의 휴대폰이나 다른 컴퓨터에서는 들어올 수 없어요.

Q. Codex·Claude도 API 키를 넣어야 하나요?

아니요. 두 명령어 도구는 원래 쓰던 로그인을 그대로 써요. 연결할 때 진단이 설치와 로그인부터 확인하고, 막히면 안내를 띄워요.

Q. 새 AI를 붙이려면 무엇을 바꾸나요?

어댑터 파일 하나를 만들고 목록에 한 줄 등록해요. 창구·교통정리·흘려보내기는 그대로 써요.

Q. 답이 잘렸는지는 어떻게 아나요?

기록 한 줄의 끝난 이유를 봐요. 정해 둔 길이를 다 써서 잘렸으면 그 줄이 경고로 표시돼요. 자세한 사연은 4부에서 다뤄요.

다음 편은 “‘OpenAI 호환’은 왜 표준 콘센트가 됐나”예요. 중계기가 왜 하필 그 모양으로 창구를 열었는지, 호환을 어디까지 믿을 수 있는지 이야기할게요.
