Claude 401 오류, 로그인했는데 옛 API 키가 먼저 쓰인 이유 (LLM 중계기 개발기)

Claude 401 오류 — 로그인했는데 옛 API 키가 먼저 쓰인 이유 (캐릭터는 GPT 이미지 생성)

Claude에 분명히 로그인해 뒀는데 401 오류가 돌아온 적 있나요? “로그인했는데 왜 인증 실패지?” 제가 만든 LLM 중계기를 처음 만든 날, 바로 이 일이 있었어요.

현관 도어락을 휴대폰 키로 바꿨다고 해 볼게요. 휴대폰을 대면 문이 열려야 하는데, 도어락은 “등록되지 않은 카드입니다”라는 소리만 내요. 알고 보니 휴대폰 케이스 안에 예전 카드키가 그대로 꽂혀 있었어요. 도어락은 휴대폰보다 그 카드를 먼저 읽었고, 그 카드는 이미 등록이 지워진 카드였죠.
로그인은 멀쩡했어요. 컴퓨터에 남아 있던 옛 API 키가 먼저 쓰여 문을 막았어요.

지난 7편에서는 AI 프로그램이 켜진 폴더의 메모를 읽어 오는 바람에 빈 전용 폴더를 마련한 이야기를 했어요. 이번에는 폴더가 아니라 컴퓨터 전체에 붙어 있던 메모 한 줄이 말썽을 부린 이야기예요.

옛 카드키를 거절당하고 새 휴대폰 키를 든 로봇 — 먼저 꽂힌 옛 열쇠 (GPT 이미지 생성)

1. 증상: 로그인했는데 401

버전 확인은 멀쩡한데, 중계기가 Claude에게 말을 걸면 401이 돌아왔어요. 중계기를 만든 첫날, 7월 13일의 일이에요. 4편의 첫날 기록에서 한 줄로 지나갔던 바로 그 문제예요.

어떤 윈도 컴퓨터에서 중계기에 Claude를 연결하면 실패했어요. 확인한 것을 표로 정리했어요.

확인한 것결과
명령창에서 Claude 버전 확인정상 — 설치에는 문제없음
Claude 계정 로그인해 둔 상태
중계기가 Claude에게 질문401 — Invalid authentication credentials (인증 정보가 올바르지 않음)

401은 웹에서 흔히 쓰는 상태 번호로, “누구인지 확인이 안 된다”는 뜻이에요. 열쇠가 없거나 맞지 않을 때 나와요. 버전 확인은 서비스의 문을 두드리지 않는 일이라 열쇠 문제가 드러나지 않았어요. 문 앞까지 가서야 탈이 난 거예요.

2. 환경 변수: 컴퓨터 전체에 붙인 메모

환경 변수는 컴퓨터 전체에 붙여 둔 메모 같은 설정값이에요. ‘이름 = 값’ 모양의 짧은 메모가 여러 장 붙어 있고, 프로그램들은 켜질 때 이 메모 묶음을 읽어 가요.

① “임시 파일은 이 폴더에 둬” 같은 메모
② “이 프로그램을 찾으려면 이 폴더들을 뒤져 봐” 같은 메모
③ 그리고 가끔은 “이 서비스의 열쇠(API 키)는 이거야” 같은 메모

환경 변수는 평소에 열어 볼 일이 거의 없어요. 한 번 넣어 두면 서랍 속 물건처럼 눈에 띄지 않은 채 그대로 남아 있죠.

규칙이 하나 더 있어요. 켜진 프로그램은 켠 프로그램의 메모 묶음을 그대로 물려받아요. 중계기는 Claude에게 질문을 전할 때 Claude 프로그램을 직접 켜서 불러요(6편에서 다룬 이야기예요). 그러니 그 컴퓨터의 환경 변수가 전부 Claude에게 넘어갔어요.

3. 원인: 열쇠가 두 개였다

그 컴퓨터의 환경 변수에 API 키가 남아 있었고, Claude는 로그인보다 그 키를 먼저 썼어요. 메모의 이름은 ANTHROPIC_API_KEY였어요. Claude를 만든 앤트로픽의 API 키를 담는 자리예요. Claude 입장에서는 열쇠가 두 개였던 셈이에요.

① 환경 변수에 남아 있던 API 키
② 명령어 도구에 해 둔 계정 로그인

중계기가 Claude를 부르는 방식에서는, 환경 변수에 API 키가 있으면 Claude가 로그인보다 그 키를 먼저 썼어요. 그 키는 문을 열지 못하는 키였고, 결과는 401이었어요. 로그인은 멀쩡히 살아 있었는데 차례가 오지 않은 거예요.

전: 환경 변수의 키가 먼저 쓰여 401 / 후: 건네는 사본에서 키를 지워 로그인으로 문이 열림 (직접 제작)

4. 해결: 건네는 메모에서 그 열쇠만 뺐다

중계기가 Claude를 켤 때 건넬 메모 묶음을 직접 만들어, 사본에서 API 키만 지웠어요.
① 중계기가 들고 있는 메모 묶음(환경 변수)을 복사해요.
② 사본에서 API 키 메모와, 같은 역할을 하는 인증 토큰 메모를 지워요.
③ 그 사본을 Claude에게 건네요.

이제 Claude 손에 남은 열쇠는 계정 로그인 하나뿐이라, 로그인으로 문을 열어요. 첫날 오후 1시 44분의 수정이었어요.

이 방법에서 신경 쓴 점이 두 가지 있어요.
① 컴퓨터의 설정은 건드리지 않아요 — 지우는 건 Claude에게 건네는 사본뿐이에요. 그 키를 일부러 쓰는 다른 프로그램은 영향을 받지 않아요. 옛 열쇠를 버리지 않고 상자에 따로 넣어 두는 셈이죠.
② 로그인 파일도 건드리지 않아요 — 중계기는 Claude의 로그인 정보를 직접 만들거나 고치지 않아요. 사람이 명령어 도구에서 한 로그인을 그대로 써요.

같은 일이 다시 생기지 않도록 “컴퓨터에 API 키가 있어도 Claude에게 건네는 사본에는 없어야 한다”는 자동 검사도 붙였어요.

5. 남긴 규칙: 어떤 열쇠를 썼는지 말한다

“인증 실패”라는 말만으로는 어느 열쇠가 실패했는지 알 수 없어서, 규칙을 세 가지 남겼어요.
① 열쇠의 순서는 중계기가 정해요 — Claude는 명령어 도구의 로그인으로 부른다고 정하고, 그 순서를 흔드는 메모는 건네지 않아요.
② 어떤 열쇠를 썼는지 함께 적어요 — 연결에 성공하면 연결 완료 표시 옆에 “인증: CLI 로그인 (머신의 ANTHROPIC_API_KEY는 무시함)”처럼 적혀요. 열쇠의 값은 보여 주지 않아요.
③ 401에도 원인이 여럿이에요 — 닷새 뒤에는 401이 났을 때 할 일을 정확한 명령으로 안내하도록 고쳤어요. 새로 설치한 컴퓨터에서 가장 흔한 401은 아직 로그인을 하지 않은 경우였거든요.

열쇠를 순서대로 정리하는 로봇 — 어떤 열쇠를 먼저 쓸지는 중계기가 정한다 (GPT 이미지 생성)

지금의 중계기는 쓰는 쪽 프로그램에 실패를 돌려줄 때 번호를 나눠 써요.

번호뜻과 할 일
401누구인지 확인이 안 됨 — 그 AI가 중계기에 연결돼 있지 않으니 관리 화면에서 연결부터
403누구인지는 알지만 못 들어감 — 관리 화면에서 그 AI나 모델을 ‘사용 안 함’으로 꺼 둠
429너무 많이, 너무 자주 — 대기 줄이 가득 찼거나, 분당 한도에 걸렸거나, 사용 한도를 다 씀

같은 429라도 ‘잠깐 붐빔’과 ‘사용 한도를 다 씀’은 따로 표시해요. 한도를 다 쓴 경우는 금방 다시 시도해도 풀리지 않으니, 기다릴 시간을 길게 알려 줘요.

Claude의 실패도 ‘설치가 안 됨’, ‘로그인이 필요함’, ‘사용 한도를 다 씀’처럼 갈래로 나눠, 갈래마다 할 일을 다르게 안내해요. 로그인 만료 안내문이 정상 답처럼 도착한 날의 이야기는 17편에서 따로 할게요.

💡 핵심실패를 알릴 때는 무엇이 실패했는지까지 함께 적어야, 다음 사람이 헤매지 않아요.

적용해 보기

Claude Code에 로그인했는데 다른 프로그램을 거치면 401이 난다면, 이 순서로 확인해 보세요. (윈도 PowerShell 기준)

  1. PowerShell을 열고 아래 두 줄을 한 줄씩 입력하세요.
claude auth status
Test-Path Env:ANTHROPIC_API_KEY

→ 첫 줄은 Claude Code의 로그인 상태를 보여 줘요. 로그인이 없으면 claude auth login으로 로그인부터 하세요. 새로 설치한 컴퓨터에서 가장 흔한 401이에요.
→ 둘째 줄이 True면 환경 변수에 API 키가 남아 있는 거예요. 값은 보여 주지 않고 있는지 없는지만 알려 주는 명령이에요.

⚠️ 주의API 키 값은 화면에 띄우거나 캡처해서 남에게 보내지 마세요. 있는지 없는지만 확인하면 충분해요.

남아 있다면 지우기 전에 그 키를 일부러 쓰는 프로그램이 있는지 먼저 확인하세요. 중계기처럼, AI를 부르는 쪽에서만 빼 주는 방법도 있어요.

자주 묻는 질문

Q. 버전 확인이 되면 연결도 되는 것 아닌가요?

아니요. 버전 확인은 서비스의 문을 두드리지 않아서 열쇠 문제가 드러나지 않아요. 실제로 질문을 보내 봐야 알 수 있어요.

Q. 환경 변수의 API 키를 지워야 하나요?

그 키를 일부러 쓰는 프로그램이 있을 수 있어요. 중계기는 컴퓨터 설정은 그대로 두고, Claude에게 건네는 사본에서만 뺐어요.

Q. 401과 403은 어떻게 다른가요?

401은 누구인지 확인이 안 될 때, 403은 누구인지는 알지만 들어갈 수 없을 때예요. 중계기에서는 403이면 관리 화면에서 그 AI나 모델을 꺼 둔 경우예요.

다음 편에서는 2부를 마무리해요. 모델마다 다른 스펙을 프로그램이 읽을 수 있게 카드로 만든 이야기예요.
