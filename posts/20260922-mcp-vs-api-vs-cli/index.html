MCP vs API vs CLI 차이, 언제 무엇을 쓸지 한 표로

MCP vs API vs CLI 차이 — 언제 무엇을 쓸지 한 표로 (캐릭터는 GPT 이미지 생성)

AI 글을 읽다 보면 세 단어가 늘 같이 나와요. MCP, API, CLI. “MCP 서버를 연결하라는데, API랑 뭐가 다르지?” 하는 데서 멈추게 되죠.

거실에 기계가 여럿 있다고 해 보세요. 몸체에 달린 버튼을 누르거나, 기기마다 딸린 리모컨을 쓰거나, 모든 기기의 기능이 한 화면에 뜨는 통합 리모컨을 쓸 수 있어요. 무엇이 제일 좋은지는 누가, 얼마나 자주, 무엇을 하려는지에 따라 달라요.
CLI는 몸체의 버튼, API는 기기별 리모컨, MCP는 통합 리모컨 규격이에요.

도구함, 리모컨 다발, 통합 리모컨 가운데 통합 리모컨을 가리키는 로봇 — MCP·API·CLI 비유 (GPT 이미지 생성)

③ 상황별로 무엇을 고를지

1. 한 표로 보는 차이

셋을 가르는 기준은 누가 부르고, 무엇을 부를지 누가 정하느냐예요. 공식 문서와 제 블로그 공장에서 쓰는 방식을 기준으로 한 줄씩 정리했어요.

방식누가 부르고 누가 고르나
CLI (명령줄)사람이나 터미널을 쥔 AI가 명령어를 쳐서 부른다
API (응용 프로그램 인터페이스)프로그램이 정해진 양식으로 부른다 — 양식은 서비스마다 다르다
MCP (모델 컨텍스트 프로토콜)AI 앱이 도구 목록을 받아 스스로 골라 부른다 — 공용 규격

표의 둘째 칸이 핵심이에요. 어느 도구를 쓸지 사람이 코드에 적어 두면 API, AI가 목록을 보고 고르면 MCP예요.

2. CLI: 기계에 달린 버튼

CLI(Command Line Interface)는 검은 창(터미널)에 글자로 명령을 치는 방식이에요. 마우스 대신 글자로 누르는 버튼이라고 보면 돼요. 가장 쉽게 만져 보는 방법은 터미널에 이 한 줄을 치는 거예요.

git --version

→ 검은 창이 git 버전으로 답하면 CLI를 쓴 거예요.

CLI는 사람만 쓰는 게 아니에요. 클로드 코드는 그 자체가 CLI이면서, 작업 중에 다른 CLI를 불러요. 9월 22일 이 글을 쓸 때 세어 보니, 제 저장소의 자동화 코드 6개 파일이 git·Edge·npm을 명령으로 불렀어요. 릴스도 ffmpeg 명령 한 줄로 만들어요.

대신 명령어를 알아야 해요. 버튼이 어디 있는지 모르면 못 누르죠. 그래서 AI도 CLI를 쓸 때는 사용법을 이미 알거나 문서를 먼저 읽어요.

3. API: 기기별 리모컨

API는 프로그램이 다른 프로그램(대개 인터넷 너머의 서비스)에 일을 시키는 약속이에요. ‘이 주소로, 이 항목을 채워, 이 열쇠(키)를 붙여 보내면 이런 답을 준다’가 정해져 있어요.

제 블로그의 예를 들면, 이 글의 삽화는 파이썬 스크립트가 OpenAI 이미지 API에 정해진 양식으로 요청해서 받아 온 거예요. 여행 글 재료는 GitHub API로 이슈를 읽어 와요. 두 API는 주소도, 항목 이름도, 인증 방식도 달라요. 리모컨이 기기마다 다른 것과 같아요.

그래서 API는 사람이 직접 누르지 않아요. 개발자가 코드에 순서를 적어 두고, 프로그램이 그대로 눌러요.

4. MCP: 통합 리모컨 규격

MCP는 AI 앱이 도구 목록을 받아, 필요한 것을 스스로 골라 부르게 하는 공용 규격이에요. MCP 공식 문서는 MCP를 ‘AI 애플리케이션을 외부 시스템에 연결하는 오픈소스 표준’이라고 정의하고, ‘AI 앱을 위한 USB-C 포트’에 빗대요.

움직이는 순서는 세 단계예요.
① 호스트(클로드 코드 같은 AI 앱)가 서버(도구를 내놓는 프로그램)마다 연결을 하나씩 만들어요.
② AI 앱이 먼저 tools/list로 어떤 도구가 있는지 목록을 받아요.
③ 그중 하나를 골라 tools/call로 불러요. 메시지 형식은 JSON-RPC 2.0 하나라서, 같은 컴퓨터 안이든 인터넷 너머든 같아요.

메뉴판(도구 목록)을 건네는 웨이터 로봇과 그중 하나를 고르는 손님 로봇 (GPT 이미지 생성)

9월 22일 이 글을 처음 쓸 때 제 클로드 코드 세션에는 MCP 서버 9개가 붙어 있었고, 그중 6개(Figma·Gmail·구글 캘린더·구글 드라이브·노션·슬랙)가 인증된 상태였어요. 제가 ‘이 파일 드라이브에 올려줘’라고만 하면, AI가 도구 목록에서 드라이브 서버의 파일 만들기 도구를 골라 불러요. 어느 도구를 쓸지 사람이 코드에 적어 두지 않는다는 게 API와 가장 큰 차이예요.

5. 같은 일을 세 방식으로

말로만 가르면 헷갈리니, 보고서 파일 하나를 구글 드라이브에 올리는 일을 셋으로 해 볼게요.

CLI로 rclone이라는 프로그램(공식 소개는 ‘클라우드 저장소용 rsync’)을 설치하고, 터미널에 한 줄을 쳐요. 사람이 치거나, 터미널을 쥔 AI가 쳐요.

rclone copy ./report.pdf gdrive:backup

API로 내 프로그램이 구글 드라이브 API 공식 문서대로 업로드 주소(upload/drive/v3/files)에 파일을 실어 보내요. 인증 토큰(Authorization: Bearer)과 파일 종류(Content-Type) 헤더가 필요하고, 이 단순 업로드 방식은 5MB 이하 파일용이에요. 사람은 직접 누르지 않아요.

MCP로 AI에게 말로 시켜요.

📋 그대로 복사해 쓰세요

이 파일을 구글 드라이브에 올려줘

AI 앱이 드라이브 MCP 서버의 도구 목록에서 파일 만들기 도구(create_file)를 찾아, 이름과 내용을 채워 불러요. 그리고 그 서버는 안에서 결국 드라이브 API를 불러요.

구글 드라이브에 파일 올리기를 CLI·API·MCP로 — 누가 부르나, 양식은 누가 정하나, AI가 고르나 (직접 제작)

셋을 나란히 두면 경쟁처럼 보이지만, 실제로는 위아래로 쌓여 있어요.

💡 핵심셋은 경쟁이 아니라 층이에요. MCP 서버의 속은 대개 API나 CLI예요.

6. 언제 무엇을 고르나

누가 누르느냐로 고르면 돼요. 상황별로 정리하면 이래요.

상황고를 것과 이유
한 번 하는 일 · 내 컴퓨터의 빌드·배포CLI — 설치하면 바로 되고, 사람도 AI도 같은 명령을 쓴다
매일 정해진 순서로 도는 자동화API(코드로) — 판단이 필요 없는 일에 AI를 끼우면 느리고 비싸다
상황을 봐 가며 도구를 골라야 하는 일MCP — AI가 목록에서 고르니 순서를 적어 둘 필요가 없다
팀이 쓰는 AI 앱에 회사 도구 붙이기MCP 서버 하나 — 한 번 만들면 MCP를 지원하는 앱 어디서나 쓴다

제 블로그 공장도 이 표대로 나뉘어 있어요. 매일 아침 6시 발행 큐는 정해진 순서대로 스크립트를 명령으로 돌려요. 사이트 배포도, 그날 글 내보내기도 순서가 정해져 있어서 AI의 판단이 끼지 않아요. 반면 글을 쓰는 세션은 MCP를 써요. 클로드 코드가 필요할 때 드라이브·메일·노션 도구를 스스로 골라요.

이런 분은 CLI와 API: 같은 일을 정해진 순서로 되풀이하는 분
이런 분은 MCP: ‘이거 해줘’ 한마디로 도구 고르기까지 AI에게 맡기고 싶은 분

7. 통합 리모컨은 권한도 통합해요

MCP 서버를 붙이는 건 AI에게 권한을 주는 일이에요. 목록에 있는 도구는 AI가 고를 수 있어요. 메일 보내기·파일 삭제 같은 도구가 있다면, 언제 써도 되는지 규칙이 필요해요.

CLI를 쥔 AI도 마찬가지예요. 명령으로 할 수 있는 일은 무엇이든 할 수 있어서, 실행 전 검사(훅)를 두는 거예요. 저는 클로드 코드를 자동 모드로 쓰고, 밖으로 내보내는 일은 규칙(하루 1편 큐·발행 전 검사)을 정해 맡겨요. 처음엔 매번 직접 승인했어요.

API 키도 조심해야 해요. 제 공장은 키를 설정 파일 한 곳에서만 읽고 어디에도 출력하지 않아요.

⚠️ 주의API 키는 리모컨 배터리가 아니라 집 열쇠예요. 코드나 대화에 붙여 넣지 말고 설정 파일(.env)에만 두세요.

헷갈리기 쉬운 것

MCP가 API를 대체하는 건 아니에요 MCP 공식 문서는 도구를 ‘파일 작업, API 호출, 데이터베이스 조회 같은 동작을 수행하는 실행 가능한 함수’라고 정의해요. 드라이브 MCP 서버의 속은 드라이브 API이고, 파일시스템 MCP 서버의 속은 로컬 파일 명령이에요.

CLI는 개발자만 쓰는 게 아니에요 터미널을 쥔 AI도 CLI를 써요. 클로드 코드에 일을 시키면, 사람이 명령어를 몰라도 AI가 대신 명령을 쳐요.

API는 사람이 누르는 버튼이 아니에요 API는 프로그램끼리 정한 약속이라, 사람은 코드를 통해서만 써요. 사람이 직접 치는 쪽은 CLI예요.

✅ 한눈에 정리① CLI는 버튼 — 사람이나 AI가 명령으로
② API는 기기별 리모컨 — 프로그램이 양식대로
③ MCP는 통합 리모컨 — AI가 목록에서 골라
④ 셋은 층 — MCP 서버의 속은 API·CLI

자주 묻는 질문

Q. 비개발자도 셋을 직접 만져 볼 수 있나요?

네. 터미널에 git --version 한 줄이면 CLI예요. AI에게 ‘무료 공개 API로 데이터를 가져오는 파이썬 10줄을 써줘’라고 시켜 돌려 보면 API, 클로드 코드에 MCP 서버를 연결하고 ‘지금 쓸 수 있는 도구 목록 보여줘’라고 물으면 MCP를 만져 본 거예요.

Q. 매일 도는 자동화는 왜 MCP 말고 API로 하나요?

정해진 순서로 도는 일에는 AI의 판단이 필요 없어서요. 거기에 AI를 끼우면 느리고 비싸져요.

Q. MCP 서버는 아무거나 연결해도 되나요?

아니요. 목록에 있는 도구는 AI가 고를 수 있어서, 연결한 만큼 권한을 주는 셈이에요. 연결 전에 확인할 것은 MCP 서버 추천 글에 정리해 두었어요.

Q. 같은 일을 셋 다로 할 수 있다면 무엇부터 해 보면 좋나요?

파일 하나 올리기처럼 작은 일을 셋으로 한 번씩 해 보세요. 어느 쪽이 편했는지가 곧 내 상황의 답이에요.

다음 글에서는 클로드 코드에 MCP 서버를 직접 연결하는 방법을 다뤄요. 연결 방법 세 가지와 연결 뒤 확인하는 법까지요.
