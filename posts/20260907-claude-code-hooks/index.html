클로드 코드 훅(hooks) 활용법, 부탁 대신 규칙으로 거는 법

클로드 코드 훅 활용법 — 부탁 대신 규칙으로 거는 법 (캐릭터는 GPT 이미지 생성)

“파일 고치면 꼭 포맷터 돌려줘.” AI에게 이렇게 부탁해 본 적 있나요? 처음엔 잘 지키다가 대화가 길어지면 잊어요. AI의 기억에 맡긴 부탁이라서 그래요.

퇴근할 때 ‘불 끄고 가세요’라는 메모를 붙여 두면, 바쁜 날엔 다들 잊고 나가요. 센서 등은 사람이 나가면 누가 기억하든 말든 저절로 꺼지고요. 클로드 코드에서 CLAUDE.md가 메모라면, 훅(hooks)은 센서예요.
훅은 정해진 시점이 오면 AI의 판단과 상관없이 무조건 실행되는 규칙이에요.

벽의 메모는 그대로 두고 천장의 센서 등이 알아서 움직이는 장면 — 훅을 센서 등에 빗댄 그림 (GPT 이미지 생성)

② 걸 수 있는 시점과 설정 파일 위치

준비물: 설치한 클로드 코드 · 작업할 폴더
2026년 10월 기준 · Windows 11 · 2.1.268

1. 훅이란: 부탁이 아니라 규칙

훅은 클로드 코드가 일하는 특정 시점에, 내가 정한 명령을 자동으로 실행하는 장치예요. 도구를 실행하기 직전과 직후, 응답을 마쳤을 때, 세션을 시작할 때처럼 정해진 순간에 끼어들어요.

CLAUDE.md에 적은 지침이나 채팅으로 한 부탁은 AI가 따르려고 노력하는 것이고, 훅은 시스템이 반드시 실행하는 것이에요. 공식 문서도 훅을 ‘AI가 실행하기로 고르기를 기대하는 대신, 늘 일어나게 만드는’ 확정적인 제어라고 설명해요.

클로드 코드 훅이 끼어드는 시점 — 도구 실행 직전(PreToolUse), 직후(PostToolUse), 응답 완료(Stop) (직접 제작)

💡 핵심반드시 일어나야 하는 일은 훅에, 알려 주면 되는 일은 CLAUDE.md에 맡기세요.

2. 걸 수 있는 시점 5가지

처음엔 아래 다섯 시점이면 충분해요. 공식 문서의 이벤트 목록은 2026년 10월 7일 기준 33개인데, 자주 쓰는 건 이 다섯 개예요.

이벤트실행되는 때
PreToolUse도구 실행 직전 — 막을 수 있음
PostToolUse도구 실행이 성공한 직후
Stop클로드가 응답을 마쳤을 때
SessionStart세션을 시작하거나 다시 열 때
Notification입력·승인을 기다리며 알릴 때

여기서 도구는 파일 읽기·고치기, 터미널 명령처럼 클로드 코드가 쓰는 손발이에요. 막을 수 있는 건 실행 직전(PreToolUse)뿐이에요. 실행 뒤(PostToolUse)에는 이미 일어난 일을 되돌리지 못해요.

3. 훅을 넣는 곳과 확인하는 법

훅은 설정 파일(settings.json)의 hooks 항목에 적어요. 어느 파일에 적느냐로 적용 범위가 정해져요.

설정 파일적용 범위
~/.claude/settings.json내 모든 프로젝트
.claude/settings.json이 프로젝트 — 저장소에 올려 함께 씀
.claude/settings.local.json이 프로젝트 — 내 컴퓨터에서만

설정 파일 문법이 낯설다면 클로드 코드에게 말로 시켜도 돼요. 공식 문서도 원하는 훅을 설명하면 클로드가 대신 써 준다고 안내해요.

📋 그대로 복사해 쓰세요

파일을 고친 뒤에 prettier로 포맷하는 PostToolUse 훅을 이 프로젝트의 .claude/settings.json에 추가해줘
  1. 클로드 코드 입력 칸에 위 요청을 붙여 넣으세요.→ 설정 파일의 hooks 항목에 새 훅이 들어가요.
  2. 입력 칸에 /hooks를 입력하세요.→ 설정된 훅이 이벤트별로 보여요. 하나를 고르면 실행할 명령과 적힌 파일이 나와요.

2026년 10월 문서 기준으로 /hooks는 보기 전용 목록이에요. 훅을 넣고 고치는 건 설정 파일에서 해요. 클로드 코드가 켜져 있는 동안 설정 파일을 고쳐도, 보통은 바로 반영돼요.

4. 예시 ① 고친 뒤 자동 포맷

파일을 고칠 때마다 포맷터가 따라 돌게 하려면 PostToolUse에 걸어요. 직접 적는다면 프로젝트의 .claude/settings.json에 이런 모양으로 넣어요.

{"hooks": {"PostToolUse": [{
  "matcher": "Edit|Write",
  "hooks": [{
    "type": "command",
    "command": "npx prettier --write ."
  }]
}]}}

→ 읽는 법: Edit이나 Write 도구가 성공한 뒤에(PostToolUse) 이 명령을 실행하라는 뜻이에요.
→ 이제 클로드가 파일을 고칠 때마다 포맷터가 무조건 따라 돌아요. 부탁도, 확인도 필요 없어요.

이 명령은 폴더 전체를 포맷하는 가장 단순한 형태예요. 공식 문서 예시는 jq라는 도구로 방금 고친 파일 하나만 골라 포맷해요. 설정 파일에 이미 다른 내용이 있다면 통째로 바꾸지 말고, hooks 안에 PostToolUse 항목만 더하세요.

포맷터 대신 린터나 테스트를 걸어도 돼요. AI가 고친 코드가 규칙에 맞는지를 사람이 아니라 도구가 확인하게 돼요.

5. 예시 ② 위험 명령 막기

PreToolUse에 검사 스크립트를 걸고, 막아야 할 때 종료 코드 2로 끝내면 그 도구 실행이 막혀요. 센서 등 비유를 이어 가면, PreToolUse는 문 앞의 검문소예요. 예를 들어 운영 DB 주소가 들어간 명령은 무조건 막는 안전장치를 만들 수 있어요.

위험 표시가 붙은 상자를 검문소 차단기가 세우는 장면 — 도구 실행 직전에 서는 PreToolUse 가드를 빗댄 그림 (GPT 이미지 생성)

막을 때 스크립트가 남긴 이유는 클로드에게 전달돼요. 그래서 클로드가 막힌 이유를 보고 다른 방법을 찾아요. 검사 스크립트도 말로 시킬 수 있어요.

Bash 명령에 운영 DB 주소가 들어 있으면 실행을 막는 PreToolUse 훅을 만들어줘. 막을 때는 이유를 출력하고 종료 코드 2로 끝내줘

저는 클로드 코드를 자동 모드로 맡겨 써요. 공식 문서에 따르면 PreToolUse 훅은 권한 모드를 따지기 전에, 모든 권한 모드에서 먼저 실행돼요. 자동 모드로 맡겨도 훅 가드는 먼저 선다고 보면 돼요.

6. 예시 ③ 작업이 끝나면 알림

긴 작업을 맡겨 두고 다른 일을 하려면, 끝나는 순간을 알려 주는 훅을 걸어요. Stop은 클로드가 응답을 마칠 때마다 실행되고, Notification은 클로드가 승인을 기다리거나 응답을 마친 뒤 60초쯤 입력이 없을 때 실행돼요.

공식 문서의 첫 따라 하기 예제도 입력을 기다릴 때 데스크톱 알림을 띄우는 Notification 훅이에요.

클로드가 응답을 마치면 윈도우 알림 창이 뜨는 Stop 훅을 내 사용자 설정에 추가해줘

알림 명령은 운영체제마다 달라요. 공식 문서에 macOS·리눅스·Windows(PowerShell) 예시가 따로 있어요.
Stop은 작업이 다 끝났을 때만이 아니라 응답을 마칠 때마다 실행돼요. 질문 하나에도 알림이 오는 게 번거롭다면 Notification 쪽이 맞아요.

7. 훅을 쓰기 전 주의할 점

훅은 내 컴퓨터에서, 클로드 코드와 같은 환경으로 셸 명령을 그대로 실행해요. 프로젝트 설정 파일(.claude/settings.json)에 든 훅은 그 폴더에서 클로드 코드를 쓰면 함께 실행돼요. 남이 만든 저장소를 받았다면 그 파일의 hooks 항목부터 열어 보세요.

⚠️ 주의인터넷에서 복사한 훅 설정을 그대로 붙여 넣지 마세요. 어떤 명령인지 이해한 것, 내가 만들었거나 믿을 수 있는 스크립트만 거세요.

구분 하나만 더요. 매번 실행할 필요 없이 필요할 때 부르는 절차는 훅이 아니라 스킬(skills)이 맞아요. 예전의 커스텀 커맨드는 2026년 10월 문서 기준으로 스킬에 합쳐졌어요.
강제해야 하면 훅, 불러 쓰고 싶으면 스킬이에요.

막힐 때

/hooks에 훅이 보이지 않아요
원인: 설정 파일의 문법이 틀렸거나 파일 위치가 다를 때가 많아요. JSON에는 끝 쉼표와 주석을 쓸 수 없어요.
해결: 위치를 3번 표와 대조하세요. 몇 초 뒤에도 안 보이면 세션을 다시 시작하세요.

훅이 있는데 실행되지 않아요
원인: matcher의 도구 이름은 대소문자를 구분해요. edit|write처럼 쓰면 맞지 않아요.
해결: Edit|Write처럼 도구 이름을 정확히 쓰세요.

hook error라는 메시지가 떠요
원인: 훅 명령이 0이 아닌 종료 코드로 끝났어요. 명령이 설치돼 있지 않거나 경로가 틀린 경우가 많아요.
해결: 그 명령을 터미널에서 직접 실행해 보고, 필요한 도구를 설치하거나 경로를 고치세요.

③ 막기는 PreToolUse, 후처리는 PostToolUse
④ 이해한 명령, 믿을 수 있는 스크립트만

자주 묻는 질문

Q. 코딩을 몰라도 훅을 쓸 수 있나요?

원하는 동작을 말로 설명하면 클로드 코드가 설정 파일에 훅을 써 줘요. 다만 무엇을 실행하는 명령인지는 /hooks로 열어 보고, 이해한 뒤에 두세요.

Q. CLAUDE.md가 있는데 훅도 필요한가요?

역할이 달라요. CLAUDE.md는 클로드가 따르려고 노력하는 지침이고, 훅은 시스템이 반드시 실행하는 규칙이에요. 꼭 지켜야 하는 것만 훅으로 옮기세요.

Q. 자동 모드에서도 훅이 실행되나요?

네. 공식 문서에 따르면 PreToolUse 훅은 모든 권한 모드에서, 권한을 따지기 전에 먼저 실행돼요.

Q. 훅을 잠시 모두 끄려면요?

설정 파일에 "disableAllHooks": true를 넣으면 돼요. 프로젝트 설정이 내 설정보다 앞설 수 있으니, 끈 뒤에 /hooks로 확인하세요.
