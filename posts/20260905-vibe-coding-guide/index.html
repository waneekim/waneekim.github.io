이 글에는 제휴 링크가 없습니다. 언급된 어떤 도구 업체로부터도 대가를 받지 않았습니다.

바이브 코딩이 뭐길래 — 뜻부터 도구 선택까지, 직접 만든 실물 2개로 설명

“바이브 코딩 한번 해보세요”라는 말을 듣고 검색창을 열었다면, 이 글 하나로 끝내자. 뜻 → 실제로 되는 건지 → 뭘로 시작할지 순서로 간다. 이론이 아니라 내가 실제로 만든 결과물 2개로 설명한다.

결론 요약

  • 바이브 코딩 = 코드를 직접 치는 대신, AI에게 말로 요구하고 결과물을 보며 다듬는 개발 방식
  • 비개발자도 실제로 쓸모 있는 걸 만들 수 있다 — 단, “한 번에 완성”이 아니라 **“보면서 고치는 반복”**이 핵심
  • 시작 도구는 목적에 따라 갈린다: 하나 만들어보고 싶다 → 대화형(ChatGPT/Codex), 프로젝트를 굴리고 싶다 → 에이전트형(Claude Code 등)

💡 1. 뜻: 코드가 아니라 “분위기(vibe)“로 개발한다

바이브 코딩은 2025년 2월, AI 연구자 안드레이 카르파티(Andrej Karpathy)가 X에 올린 글에서 시작된 표현이다 — “바이브에 몸을 맡기고, 코드가 존재한다는 것조차 잊어버리는 새로운 코딩”. 요지는 이렇다: 코드를 한 줄씩 이해하며 짜는 게 아니라, AI에게 원하는 것을 말하고 → 나온 결과물을 써보고 → “여기가 별로야, 바꿔줘”라고 다시 말하는 개발 방식. 개발 지식이 아니라 “무엇이 좋은 결과물인지 판단하는 감각”이 실력이 되는 방식이다.

🧪 2. 실제로 되나? — 내가 만든 실물 2개

실물 ①: 대화만으로 만든 가족 여행 앱 (비개발 방식)

5가족 19명 여행을 준비하며 Codex(ChatGPT)와 대화로 일정을 짜고, 그 일정을 담은 앱까지 만들었다. 코드는 한 줄도 안 봤다. 첫 버전은 글자만 빽빽해 폐기했고, “전부 보물지도 그림으로 만들어줘”라는 방향 전환 한 번으로 성공했다. 실제 여행에서 잘 썼다.

→ 전 과정 기록: Codex로 일정 짜고 앱까지 만들어서 다녀왔다

여기서 배운 바이브 코딩의 본질: 프롬프트를 정교하게 다듬는 것보다, 결과물을 보고 방향을 바꾸는 판단이 승부처다.

실물 ②: AI 에이전트로 구축한 콘텐츠 운영 시스템 (반개발 방식)

지금 읽고 있는 이 블로그의 발행 시스템(저장소 구조, 사이트, 배포 파이프라인)은 Claude Code라는 AI 에이전트가 구축했다. 대화형과 결정적으로 다른 점: AI가 내 컴퓨터에서 직접 파일을 만들고, 명령을 실행하고, 결과를 스스로 검증한다. 나는 방향 결정과 승인만 했다.

두 방식을 오가며 배운 것을 한 문장으로 줄이면 이렇다.

생각보다 “코드를 어떻게 작성하는가”가 아니라 “내가 무엇을 원하는가”가 중요했다. ‘어떻게’를 채우려 하지 말고 ‘무엇’에 집중해서 요구할수록 더 좋은 앱이 나왔다.

🧰 3. 도구는 세 유형이다

유형무엇이런 사람에게대표 도구
💬 대화형채팅으로 결과물 생성, 복붙으로 사용처음 한 번 만들어보고 싶은 비개발자ChatGPT(Codex), Claude, Gemini
🤖 에이전트형내 컴퓨터·저장소에서 직접 작업프로젝트를 계속 굴릴 사람, 개발자Claude Code, Codex CLI, Cursor, Copilot
🧱 앱 빌더형브라우저에서 앱 생성·호스팅까지만든 걸 바로 공유하고 싶은 사람Replit, v0, Lovable, bolt.new

정직 고지: 내가 실제로 써본 것은 ChatGPT(Codex)와 Claude Code 두 가지다. 위 표의 나머지는 소개일 뿐 추천이 아니다. 써본 두 가지에 대해서는 분명히 말할 수 있다 — 시작이라면 이미 구독 중인 대화형부터, 계속 만들 거라면 에이전트형이 맞다.

🏁 4. 시작하는 법 (오늘 30분)

방법이라기보다 리듬이다. 아래 루프를 몸에 익히는 게 전부다.

  1. 이미 쓰는 AI 채팅(ChatGPT든 Claude든)에 이렇게 요청해보자: “[내 상황]에 쓸 [결과물]을 HTML 파일 하나로 만들어줘” — 단일 HTML은 설치 없이 브라우저로 바로 열 수 있어 첫 실험에 최적이다
  2. 결과물을 열어보고, 마음에 안 드는 점을 기능이 아니라 사용자 관점으로 말하자 (“버튼을 키워줘”보다 “초등학생도 쓸 수 있게 해줘”)
  3. 3~4번 반복해도 방향이 안 잡히면, 고치지 말고 컨셉을 바꿔서 다시 시켜라 — 내 여행 앱도 그렇게 살아났다

⚠️ 5. 한계도 알고 시작하자

  • AI가 처음 준 “완성품”이 실사용을 통과한다는 보장이 없다 — 내 1호 앱은 폐기됐다
  • 사실 정보(가격, 운영시간, 수치)는 AI 산출물을 그대로 믿으면 안 된다
  • 만든 걸 유지보수·확장하려는 순간 난이도가 뛴다 — 그때가 에이전트형으로 넘어갈 때다
